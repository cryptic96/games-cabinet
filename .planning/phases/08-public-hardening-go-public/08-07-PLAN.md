# Plan 08-07: The app answers only to its own hostnames, within limits fit for the internet

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 8`): "The site is reachable from the internet over HTTPS through the existing reverse proxy, resilient to traffic floods and unable to starve the other guests on the host, and the owner opens it only after a go-public checklist passes."

Coverage note: Claude's-discretion items of the context (Kestrel request limits, host filtering) plus the research's runtime-memory question (Open Question 3). This plan lifts one prohibition.

<objective>
Prove host filtering end to end (the framework's `AllowedHosts`, set from the server env file in production) and add validated Kestrel limits for a public host: connection ceiling, request body size and request-header timeout, leaving keep-alive at its default. Log once at start what memory limit and processor count the runtime sees.

Purpose: a request for a host the site does not serve is refused, slow or oversized requests cannot hold the app, and the container check can confirm the GC sees the unit's memory limit.
Output: `HostLimits.cs`, its wiring, `HostFilteringTests`, `KestrelLimitsTests`, `HostLimitSettingsTests`.
</objective>

## Trust Boundaries

| Public listeners to the ops listener | Kestrel limits are server-wide across all listeners |

| T-08-07-01 | Spoofing | Host header injection, DNS rebinding | low | mitigate | `AllowedHosts` from the env file; foreign host 400 on every listener (Task 1) |
| T-08-07-02 | Denial of service (self) | Host filtering without loopback rolling back releases | high | mitigate | Test proves loopback health needs the loopback entry (Task 1); env example carries it (plan 08-06); set before the release in plan 08-12 |
