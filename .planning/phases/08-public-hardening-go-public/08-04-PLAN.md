# Plan 08-04: Browser tests that wait on the live channel stop flaking

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 8`): "The site is reachable from the internet over HTTPS through the existing reverse proxy, resilient to traffic floods and unable to starve the other guests on the host, and the owner opens it only after a go-public checklist passes."

Coverage note: the plan sits in wave 4 (depending on 08-08, the last code plan with browser runs) only so that its 10-run gates run alone on the machine; it changes no file another plan changes. It carries no requirement of its own (it hardens browser tests and adds no SEC behaviour; it protects the CSP-violation tests and the browser suite that gate the release that goes public). The first half of the folded todo "Harden the browser tests that flake on the CI runner" (the live-channel waits); the card-dialog and back-button half follows in plan 08-09, which also closes the todo. This plan lifts one prohibition.

<objective>
Promote the end-to-end live check that already fixed the WebKit test (a spy on the page's live client plus a bounded re-send of the current status until the page has heard it) into one shared helper, and use it in `LiveLookTests` and `CardSyncTests`; replace `CardSyncTests`' fixed holds with waits for a positive event; make the sample-400 first draw in `DefaultLookIdentityTests` a retrying wait. Measure before and after under a one-core quota.

Purpose: a clean, trustworthy CI before the release that goes public (D-10 verifies "the full browser suite under the CSP"); a red check must mean something.
Output: `Infrastructure/LiveHearing.cs`, four hardened test classes, before and after failure counts in the SUMMARY.
</objective>
