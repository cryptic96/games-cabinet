# Plan 08-08: Every response carries the full security-header set, and the cabinet stays clean under it

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 8`): "The site is reachable from the internet over HTTPS through the existing reverse proxy, resilient to traffic floods and unable to starve the other guests on the host, and the owner opens it only after a go-public checklist passes."

Coverage note: this plan lifts SEC-03 adjacency (app side), SEC-03 empty and SEC-03 ordering, and one prohibition. Header values are Claude's discretion within D-06 (research "Pattern 1"): `X-Frame-Options: DENY` is sent beside `frame-ancestors 'none'` (they agree); no COEP (nothing needs cross-origin isolation); no obsolete headers.

<objective>
Grow the one-middleware CSP into the full security-header set (D-06), keep it first in the pipeline, and prove it on every response type and listener; prove in two browser engines that the page and an owner page log nothing under it; prove the BGG credit is visible in every page state at desktop and phone width (a go-public checklist item).

Purpose: SEC-03 is met by the app itself, tested with the page it protects; the proxy keeps only HSTS (plan 08-06).
Output: `SecurityHeaders.cs` (replacing `ContentSecurityPolicy.cs`), `SecurityHeadersTests` (replacing `ContentSecurityPolicyTests`), three browser test classes.
</objective>
