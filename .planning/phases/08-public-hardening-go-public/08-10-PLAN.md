# Plan 08-10: The go-public checklist and the hardening explained in the docs

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 8`): "The site is reachable from the internet over HTTPS through the existing reverse proxy, resilient to traffic floods and unable to starve the other guests on the host, and the owner opens it only after a go-public checklist passes."

Coverage note: the generic half of D-13 (the filled-in half lives in the phase record, plans 08-21 to 08-23). This plan lifts one prohibition.

<objective>
Write `docs/go-public.md` (the reusable checklist, the switch and how to close the site again) and update `docs/lxc-setup.md`, `docs/deploy.md` and `docs/bgg-sync.md` for the walls added in this phase: the two rate-limit layers explained plainly, the header split, the container and unit caps with the owner's Proxmox command, the outbound block and its keys, the new settings and the order in which host settings meet a release.

Purpose: the owner (and any later re-check) can open, verify and close the site from the docs alone, with nothing personal in the repository.
Output: one new doc and three updated docs.
</objective>

   - "What keeps the public site safe": one short paragraph per wall: the proxy's per-address rate limit and in-flight cap (refuses a flood cheaply, leaves room for several friends on one Wi-Fi), the app's much stricter limits on "sync now" and the live channel, the live channel admitting only the site's own pages, the owner router keeping its allow-list for good, the app sending the security headers while the proxy adds HSTS, the container and unit caps, the outbound block, health and operations on loopback only.

   - "The checklist": a numbered list with one line per item and the command or place that proves it, placeholders only: security headers (`CABINET_PUBLIC_HOST={public-hostname} CABINET_OWNER_HOST={owner-hostname} build/check-public-routes.sh --from-lan`); rate limits (`--burst`, plus the flood check on the proxy); health, ops and owner tools not routed publicly (the same script, then a phone on mobile data); the BGG credit visible on every page including the empty, error and phone views; the BGG terms re-read (the two official pages, or an archive capture when the live page is behind a bot check); no personal data in the repository (`build/scan-history.sh`, `build/lint.sh`); resource caps applied and verified (`cabinet-selfcheck`, the container's own limits on the Proxmox host); the outbound firewall active (`cabinet-selfcheck`); `noindex` present and no `robots.txt` that blocks crawlers from reading it; maintenance SSH keys protected by a passphrase and loaded into an agent only while maintenance is under way; the reverse proxy's own SSH limited to admin addresses.

   - "Closing it again": put the allow-list middleware back on the public router; the site is closed as soon as the proxy reloads the file.
   - "Re-checking later": run the script and the selfcheck after proxy changes and releases.
