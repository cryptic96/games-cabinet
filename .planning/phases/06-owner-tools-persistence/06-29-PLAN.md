# Plan 06-29: Release v0.7.0 with the owner tools switched off by default

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6`): "From the home network or VPN only, the owner can correct box images (and, if BGG cannot supply storage locations, define and assign them), with that data surviving syncs, restarts and releases and being backed up."

<objective>
Ship the phase as release v0.7.0 through the established path (pull request, checks, the owner's merge approval, attested tag draft verified on the workstation, owner-approved publish, pull-based deploy), and confirm on the container that the release is healthy with the owner endpoint still off.

Purpose: the owner tools reach the server safely before the owner opens their road (CONTEXT "Review flow": a release the owner approves after the draft check).
Output: v0.7.0 on the container, sanitised evidence in the SUMMARY.

Plan shape (why five tasks and two owner checkpoints): the two checkpoints gate two different irreversible acts at two different moments and cannot be merged without breaking the owner's standing rule. The first (Task 2) comes before anything exists to verify: the owner approves merging into `main` and pushing the tag. The second (Task 4) can only come after the attested draft exists and Claude has told the owner it is verified: the owner then approves the deploy environment, which publishes. Asking for both at once would make the owner approve a publish before the draft was checked. Only Tasks 3 and 5 are executor work; Task 1 is the pull request. This is the same shape the previous release plan ran successfully.
</objective>
