# Plan 06-09: The Locations page's first forms, and the single writer's rules

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6`): "From the home network or VPN only, the owner can correct box images (and, if BGG cannot supply storage locations, define and assign them), with that data surviving syncs, restarts and releases and being backed up."

<objective>
Put the owner's hand on the data tracer: the Locations page on the owner port adds a location and places a game through real forms, and the single writer gets its rules (name rules, no-op, out of date, Undo, refused while unreadable, token required, JSON or redirect answers) (LOC-03, LOC-04; D-16, D-27 log entries).

Purpose: the HTTP edge of owner data, with the behaviour every later owner page relies on.
Output: the Locations page (its no-script forms), `OwnerResponses`, `LocationNames.Validate`, Undo in the writer, `OwnerSession`, `OwnerTestKit`, tests.
</objective>

    - Names: `"  Shelf B  "` is stored as `Shelf B`; empty, whitespace-only, 61 characters, a 51st location, `shelf b` when `Shelf B` exists, a name holding U+0007, U+202E or U+2066 are each refused with their own reason.
    - Store: round trip; a newer `schemaVersion`, a wrong `kind`, truncated JSON and a null required member each give `Unreadable` and leave the file's bytes and name unchanged; no temporary file is left after a save.
    - Service: assigning the same location twice gives `NoChange` with the same revision, no new log entry, and the publisher's version unchanged; a mutation with an older revision gives `OutOfDate` and writes nothing; undo right after a change restores the previous document under a higher revision, removes its log entry and lowers `ChangesSinceDownload`; undo after another change, or a second undo, gives `OutOfDate` and changes nothing; every write is refused with `Unreadable` while the file is unreadable; the log keeps at most 200 entries while `ChangesSinceDownload` keeps counting past 200.
    - Integration: a JSON post with a stale revision answers 409 with `outcome` `outOfDate`; a post without a token answers 400 and changes nothing; adding a duplicate name answers 422 with the duplicate message.
