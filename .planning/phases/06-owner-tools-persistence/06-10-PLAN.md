# Plan 06-10: Owner data that lasts - earlier versions, the 30-day rule, surviving syncs and restarts, quiet live updates

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6`): "From the home network or VPN only, the owner can correct box images (and, if BGG cannot supply storage locations, define and assign them), with that data surviving syncs, restarts and releases and being backed up."

<objective>
Make the owner data durable around the sync: prove it survives a sync round, a restart and a release, keep earlier versions so a wrong edit can be undone by hand, forget games that left the collection only after 30 days of accepted snapshots, and tell open pages about owner saves once per burst (D-20, D-21, D-22, D-26, orchestrator decision 2).

Purpose: OWN-02's "survives syncs, restarts and new releases", and the live refresh every later owner page relies on.
Output: version rotation in the store, reconcile and system writes in the writer, the publisher's trigger, `OwnerChangeNotifier`, and their tests.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Sync results to owner data | Accepted snapshots start and stop the 30-day clocks |
| State directory files | Current owner data and its earlier versions |
| Server to open browsers | Live notifications carry the collection version only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-10-01 | Tampering / data loss | expiry after a held-back or failed sync | high | mitigate | Reconcile runs only after a published (accepted) snapshot and never while unreadable; tests |
| T-06-10-02 | Tampering / data loss | lost owner edit when a sync commits | high | mitigate | Publisher lock, raw snapshot baseline; interleaved integration test |
| T-06-10-03 | Tampering | path traversal through version names | medium | mitigate | Versions read by index from the store's own listing; names generated server-side |
| T-06-10-04 | Denial of service | unbounded versions or notifications | low | mitigate | Ten versions kept, at most one per hour; coalesced notifications with a ceiling |
| T-06-10-05 | Information disclosure | live channel leaking owner data | low | mitigate | Notification carries the public status only (version, times); owner data never sent |
</threat_model>
