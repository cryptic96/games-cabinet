# Plan 06-15: Linked pictures stay - the token-less fetch, the background worker, and no clean-up of owner pictures

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6`): "From the home network or VPN only, the owner can correct box images (and, if BGG cannot supply storage locations, define and assign them), with that data surviving syncs, restarts and releases and being backed up."

<objective>
Build the server side that keeps an owner's linked picture alive: fetch a link through the token-less image client under the sync's caps, process it into the same kind of record the sync stores, keep its files safe from the art clean-up, fetch links without a usable copy in the background, and define when a link counts as dead (D-10, D-13, D-25 re-fetch; orchestrator decision 2).

Purpose: with the pictures tracer in place, a stored link shows on every card, and its copy can never vanish by accident.
Output: `ArtRecords`, `OwnerLinkFetcher`, `OwnerLinkWorker`, `LinkHealth`, prune protection, tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stored owner link to the server's outbound client | A stored address becomes an outbound request target |
| Image host answers to the processor | Untrusted bytes are decoded |
| Owner link files to the art clean-up | Clean-up could delete the only copy of an owner's picture |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-06-15-01 | Information disclosure | BGG token sent to the image host | high | mitigate | Token-less typed client, no auth handler, no cookies; integration test asserts no Authorization header |
| T-06-15-02 | Tampering / data loss | clean-up deleting owner pictures | high | mitigate | Owner link files added to the referenced set; clean-up skipped while owner data is unreadable; test past the grace |
| T-06-15-03 | Denial of service | huge or hostile pictures | high | mitigate | Existing byte, pixel and time caps; shared pacer; one link at a time |
| T-06-15-04 | Tampering | worker overwriting a link the owner changed meanwhile | medium | mitigate | System write applies only if the link's address is unchanged |
| T-06-15-05 | Information disclosure | link addresses in logs | low | mitigate | Categories and counts only |
</threat_model>
