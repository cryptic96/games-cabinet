# Plan 06.1-03: Your own "Check link" never waits behind the background worker

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6.1`): "From the owner pages, the owner picks the cabinet's finish for every visitor from seven furniture looks, each with its own wall, and switches warm cubby lighting on, optionally only at night by each visitor's own clock, plus a cubby-depth look." This plan carries the owner-tools fix folded into the phase (CONTEXT D-35).

Coverage note: no SPEC; the spec-less probe fallback was skipped visibly; no probe-derived Edge Coverage or Prohibition predicates exist for this run.

<objective>
Give the owner's interactive "Check link" its own fetch slot (owner decision P6-A): a second picture pacer and a second picture client used only by the Pictures page's check, while the background link worker keeps sharing the slot with the sync. Prove it with an integration test that holds the worker on a deliberately slow link while the owner checks another link (D-35, todo `2026-10-13-check-link-while-link-worker-is-busy.md`).

Purpose: the owner never sees "Couldn't fetch that picture" for a working link just because the worker is busy.
Output: the second slot, an integration test, a unit test for the gaps, updated doc comments and `docs/bgg-sync.md`.
</objective>
