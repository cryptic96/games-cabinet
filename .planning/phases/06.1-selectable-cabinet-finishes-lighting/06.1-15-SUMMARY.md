# Phase 06.1 Plan 15: Evenings only - the lights follow sunset and sunrise by each visitor's own clock Summary

With Evenings only, the lights come on 30 minutes before sunset and go off at sunrise by the visitor's own clock, from one 36-row standard-time table for a mid-European reference point plus the visitor's own summer-time flag, marked before the first paint and kept right by an open page that fades at the moment.

## What was built

- **`evening.js`:** `TABLE` (36 rows of `[day of year, sunrise, lamp on]` in standard-time minutes on the 1st, 11th and 21st of each month, rounded, lamp-on being sunset minus 30), `dayOfYear`, `standardMinutes` (linear interpolation, running on from the last row to the first row of the next year), `summerTime` (current offset below the larger of the January and July offsets), `clockMinutes` (adds 60 minutes in summer time), `isEvening` (at or after lamp-on, or before sunrise) and `msToNextChange` (today's and tomorrow's moments, with tomorrow's own summer-time flag). When `data-lights` is not `off` the head script sets `data-evening` before the first paint, then applies the tab-flag rule as before. `window.cabinetEvening` now carries `key`, `markLit`, `isEvening` and `msToNextChange`; nothing else leaks. No location is read, stored or sent. The file is about 7 KB with its docs and the table.
- **`look.js`:** `changeLamp` moves the lamp to what the attributes say (fading hint set before the lit marker, tab flag written on a fade in, nothing under a fade of 0 ms). `start` is now `settled` plus `changeLamp`. `followClock(doc)` (exported, idempotent per page) checks the clock at once, every 60 seconds while the page is visible, on `visibilitychange`, and with one boundary timer for evenings only that is cleared and set again each time it fires. `applyClock` sets or removes `data-evening` (removes it with lights off) and calls `changeLamp`. `initLook` starts it after the first settle.
- **Tests:** `SunsetTableTests` (4 cases plus the row-order and the two solstice anchors: 21 December 08:46 and 16:30, 21 June 05:20 and 22:04 with summer time), `evening.test.mjs` (12 node checks), 8 new checks in `look-lamp.test.mjs`, and 11 new browser cases in `LightsTests` (winter evening and day, summer before and after lamp-on, lamp-on and sunrise crossed on an open page with and without the tab flag, visibility catch-up, reduced motion, no dusk in the evening). `LightsTests` now runs in a Central European zone.

### Interpretation notes

- Tests were written after the tracer code rather than before it; each test group was then proven against a mutation of the code (see Teeth), so none of them is vacuous.
- The C# oracle uses the astronomical almanac's low-precision solar position, a different method from the NOAA spreadsheet formulae the table was generated with, so the two share no code or formulation. The table was generated in a scratch script (not committed) at 52 degrees north, 5 degrees east for 2027.
- `followClock` starts from `initLook` for every page that shows the cabinet; with lights Off the interval does nothing (the head script is not loaded), so a live look switch only has to load the head script and call `followClock` again (it is idempotent).
- `ReducedMotionTests` was run as the plan asks, and the reduced-motion evening case lives in `LightsTests` so the plan's file list holds.
