# Plan 06.1-01: The default look is guarded - a zero-pixel comparison against the released stylesheets

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6.1`): "From the owner pages, the owner picks the cabinet's finish for every visitor from seven furniture looks, each with its own wall, and switches warm cubby lighting on, optionally only at night by each visitor's own clock, plus a cubby-depth look." Criterion 2's "seven finishes" now means seven designs combined with five woods (CONTEXT D-01).

Coverage note: there is no SPEC for this phase; the spec-less probe fallback was skipped visibly (no requirement IDs to probe), so no probe-derived Edge Coverage or Prohibition predicates exist for this run. must_haves derive from the ROADMAP success criteria, the CONTEXT decisions, the owner's planning decisions and the UI-SPEC.

<objective>
Write the first test of the phase before any stylesheet changes: today's look (Classic + warm brown + wood backs + Shaded + lights Off) must stay pixel-identical to the current release (D-05, UI-SPEC "The frozen default" and "Verification contract" item 1). Research Pattern 1 replaces committed baseline PNGs with an A/B render in one browser session against byte copies of the released stylesheets, which removes font, machine and layout-version differences.

Purpose: every later change to shared structure (the four layers, the hooks, the room tokens) is proven to leave the default look untouched.
Output: `Cabinet.BrowserTests/LegacyStyles/` (frozen copies), a pixel comparison helper and `DefaultLookIdentityTests`, green against today's CSS.
</objective>
