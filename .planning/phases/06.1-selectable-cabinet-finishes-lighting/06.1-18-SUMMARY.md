# Phase 06.1 Plan 18: A new design never scrolls the visitor away - in Chrome and in Safari's engine Summary

A live design change now notes the section in the middle of the screen, applies the design with native scroll anchoring switched off, and scrolls that section back to within 2 px of where it was; a look that arrives while a box is being pulled out waits until the pull-out is over; the place keeping is proven in Chromium and WebKit, with a WebKit install and run step in CI.

## What was built

- **`look-switch.js`:** exported `sectionAtCentre(rects, viewportHeight)` (the section containing the viewport centre, the nearest one when the centre is in a gap, -1 for none) and `scrollCorrection(before, after)`. For a status whose design differs, `keepPlace` notes the section and its top, sets `overflow-anchor: none` on `document.scrollingElement` with `style.setProperty`, runs the look write (inside the view-transition update, or at once), scrolls by the correction with `behavior: 'instant'` and removes the property in a `finally`. Wood, backs, depth and lights changes never touch the anchoring and never scroll. A page with no sections drawn takes the look as before.
- **Pull-out deferral:** while `<html>` carries `data-pull-kind`, the look is held; a `MutationObserver` on that attribute applies the latest held look when it goes. Several held statuses collapse to the latest, one write.
- **`build/tests/look-switch.test.mjs`:** 12 Node tests against a fake page whose sections change height with the design attribute (helpers, taller and shorter designs, view-transition path, no-scroll for other fields, no sections, hold and release, latest only, stale status while held, held look equal to the page).
- **`LiveLookTests`:** 3 new Chromium tests on the synced 400-game collection at 1440 x 900 (the live channel does not exist on the public sample pages): the third section's centre kept within 2 px after `design=library`, with the `overflow-anchor` writes recorded as `none` then removed, and no scroll or anchoring write after `wood=oak`; a pull-out held open by a gate on the view transition, a look published meanwhile applied only after release with the card still open; lights `off` to `evenings` after dusk in a Central European zone loads `evening.js` once and fades the lights on. The class now runs the browser in that time zone.
- **`LiveLookWebKitTests`:** `[Trait("Engine", "WebKit")]`, skipped with the reason "WebKit runs only where CABINET_WEBKIT=1", otherwise starts the host, launches WebKit explicitly, scrolls to the third section, publishes `design=library` from a second context through the owner port, and checks the section within 2 px, the page scrolled, and the anchoring writes.
- **`ci.yml` (`browser-tests`):** "Install WebKit" (same bundled CLI, `install --with-deps webkit`) after Chromium, and "Run WebKit tests" (`--filter-trait "Engine=WebKit"`, `CABINET_WEBKIT: 1`) after the normal run. No new actions, permissions or secrets.

## Deviations from Plan

**1. [Plan adjustment] The browser tests use the synced 400-game collection, not "sample 400"**
Public sample pages have no live channel (found in the previous plan), so a live switch cannot be tested on them. The synthetic 400-game collection gives 10 sections in 5 rows at 1440 px; 65 games gave only 2 sections, too few.

**2. [Plan adjustment] The WebKit build used here anchors natively too**
The plan (and the older design text) assumed Safari's engine does not anchor scroll positions. The WebKit build that Playwright installs now does, so the place check alone passes with or without the keeper in WebKit. The keeper's single-owner property is therefore also asserted through a spy on `overflow-anchor` writes (`none`, then removed), in both engines; this is what fails if the keeper is bypassed. The behaviour proof for an engine that really lacks anchoring stays the Node tests and the manual Safari check below.

**3. [Plan adjustment] Local WebKit needed one system library**
Playwright's host check wanted `libmanette-0.2-0`, and the headless build also `libbacktrace0`. They were downloaded as packages without root and copied into the local Playwright cache (outside the repository). Nothing in the repository depends on this; CI uses `--with-deps`.

**4. [Rule 3 - Blocking] A spy script crashed silently at page start**
The first pull-out gate script observed `document.documentElement` from an init script, where it does not exist yet, so the rest of the script never ran. It observes `document` now.
