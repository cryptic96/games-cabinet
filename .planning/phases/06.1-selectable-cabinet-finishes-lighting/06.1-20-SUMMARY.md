# Phase 06.1 Plan 20: The owner reviewed the built looks, the choices are applied and the guides describe them Summary

## Deviations from Plan

### Auto-fixed Issues

**1. [Rule 1 - Bug] Forced-colours outline inside the furniture's edge was invisible**
- **Found during:** re-shoot of the forced-colours cabinet frame
- **Issue:** the Critic's `outline-offset: -2px` on the side boards painted under the furniture's own pseudo-element layers, so the side boards, top and base did not show although the computed style was right.
- **Fix:** the outline sits just outside the edge; the test now reads a pixel of the side board.
- **Files modified:** `Cabinet.Service/wwwroot/css/cabinet.css`, `Cabinet.BrowserTests/LookForcedColoursTests.cs`
- **Commit:** 8664e23

**2. [Rule 1 - Bug] A switched-off pill took the forced-colours selection outline**
- **Found during:** forced-colours frame of the Settings panel
- **Fix:** the selection outline applies only to groups that are not disabled.
- **Commit:** 8664e23

**3. [Rule 1 - Bug] "Mahogany" clipped at exactly 64rem**
- **Found during:** measuring tile names after the widening (B7's condition)
- **Fix:** padding 4 px at the sides, description 13 px, preview column 25rem between 64rem and 72rem; a test keeps 4 px of room at four widths.
- **Commit:** 0ea9d96

**4. [Rule 3 - Blocking] The summary's no-break dots needed a server and a script change**
- **Issue:** the separator is also the change log's text, so only the displayed line changed (`OwnerStrings.SummaryLine`, `lookSummary`); the stored change-log text is unchanged. Tests that compared the displayed line were updated.
- **Commit:** ed8062a

### Choices recorded

- B8: the optional warmer birch hot line was not added (the owner asked for nothing new; it touches a lamp token and the visibility tests for a gain only in the faintest evening).
- Q7: not written into `docs/deploy.md`, which has no runtime section that this round touches; carried to the release as an operations check.
- The Q8 failure ("200 where 101 expected") never reproduced on this machine; the fix removes the two timing gaps that can cause it (an upgrade slot still held by Kestrel, and a broadcast sent before the hub registered a new connection) and is proved by the metric wait, not by a retry.
