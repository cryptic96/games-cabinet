# Phase 06.1 Plan 04: Balancing Prototype Summary

Even desktop sections via a budgeted capacity search in the layout engine, behind an off-by-default `Layout:BalanceSections` switch, with a measured before/after review and the owner's chosen stability promise recorded.

## What was built

1. **Tracer (1bc7e65):** the engine can lay out desktop sections so every section is drawn within one shelf row of every other, with no short last section. The behaviour is gated by `Layout:BalanceSections` (off by default) and a design flag that only the desktop design sets. The phone profile never balances. With the switch off the fingerprint, the layout version (15) and every recorded layout are unchanged.
2. **Review (e14b33c):** `06.1-BALANCING-REVIEW.md` with before/after desktop sheets of the 65 and 400 samples at two-column and three-column widths (`ui-refs/balancing/*.png`), counts of games moving between sections when one game is added over the 200 seeds the stability tests use, and the promise options B1, B2 and B3.
3. **Owner decision (e47daa7):** the owner's answer is recorded verbatim under "Owner's answer": B1 with the reading-order clause dropped, and setting yes.

## Measurements

- Build time on the 400-game sample, release build: about 0.9 s with balancing on, about 0.08 s with it off. This is a one-time cost per sync and the result is cached, but it is roughly ten times the plain layout and worth remembering when the switch is turned on by default.
- Tracer gate: 753 tests in `Category=Layout` passed, the recorded goldens are unchanged and `LayoutVersion` is still 15.

## Deviations from Plan

**1. [Rule 1 - plan bullet unsatisfiable] Reading-order equality**
- **Found during:** Task 1
- **Issue:** the plan asked that games keep their reading order with balancing on. Placement is first-fit, so exact reading-order equality cannot hold.
- **Fix:** replaced by tests that every game stands exactly once, series gaps are no worse than with the plain layout, and the section count is no larger.
- **Files modified:** `Cabinet.UnitTests/Layout/SectionBalanceTests.cs`
- **Commit:** 1bc7e65

**2. Engine search detail (not a plan deviation, recorded for plan 06.1-05)**
- Budgets are tried in ascending total capacity: R rows, then the first k sections at R+1 rows. The first candidate that keeps the section count and the drawn-row spread at or below 1 is accepted, otherwise the engine falls back to the plain layout. Candidates abort early, and infeasible candidates surface as a caught `InvalidOperationException`.
- **Commit:** 1bc7e65

**3. Tracer gate run automatically**
- The tracer feedback gate ran its automated verify (753 `Category=Layout` tests, goldens unchanged, `LayoutVersion` 15) instead of stopping for a human verification, because the slice is invisible with the switch off.

**4. Owner decision recorded**
- B1 with the reading-order clause removed from the wording, and setting yes. Commit: e47daa7.
