# Plan 06.1-07: Tracer for the stored look - the owner publishes a look and every page carries it from the first paint

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6.1`): "From the owner pages, the owner picks the cabinet's finish for every visitor from seven furniture looks, each with its own wall, and switches warm cubby lighting on, optionally only at night by each visitor's own clock, plus a cubby-depth look."

Coverage note: no SPEC; the spec-less probe fallback was skipped visibly; no probe-derived Edge Coverage or Prohibition predicates exist for this run.

<assumption_delta_decision>
Noun now primary: the cabinet look, five fields (design, wood, backs, lights, depth).
Decision: promote. The five-field look becomes the stored identity in owner data (schema 2). The single `finish` string is demoted to an input read only by the schema-1 upgrade and is removed from the model together with `Finishes`, `Finishes.Allowed`, `SiteFinish` and `OwnerData.DefaultFinish`.
Invariant test (accepted): every allowed value of every field round-trips save, download, restore and first paint (plan 06.1-09, Task 2).
</assumption_delta_decision>

<objective>
Build the thinnest end-to-end path of the look through every server layer: the domain look model with five allow-lists (D-01, D-06), owner data schema 2 with the schema-1 upgrade on read and restore (D-06), the site look reader, the five attributes on `<html>` of the cabinet page from the first response (D-04, D-19, D-25), and a Settings form that publishes a look without script. The old finish slot is removed (UI-SPEC "Assumptions Carried to the Planner" item 1).

Purpose: from here on, every look the CSS layers learn to draw can be published by the owner and is in every visitor's first paint.
Output: `CabinetLook`, `CabinetLooks`, `SiteLook`, schema 2, the `Look` handler and form, rewritten slot tests.
</objective>
