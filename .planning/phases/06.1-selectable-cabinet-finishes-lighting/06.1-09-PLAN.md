# Plan 06.1-09: Older data survives, a rollback finds its copy, and publishing follows the owner-page rules

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 6.1`): "From the owner pages, the owner picks the cabinet's finish for every visitor from seven furniture looks, each with its own wall, and switches warm cubby lighting on, optionally only at night by each visitor's own clock, plus a cubby-depth look."

<objective>
Finish the stored look's safety: owner decision P3-A (keep the schema bump, force a copy of the old-format file before the first new-format save, so a rollback lands on that copy), the restore path for older and newer files, the round-trip invariant the assumption-delta checkpoint asked for, and the publish rules of `Use for everyone` with Undo (D-06, D-20).

Purpose: a release that changes the owner-data format can still be rolled back without losing the owner's data, and publishing a look behaves like every other owner change.
Output: the forced copy, the round-trip test, the full look handler rules with Undo, and the rollback note in `docs/deploy.md`.
</objective>

| Boundary | Description |
|----------|-------------|
| Owner browser to owner handlers | Publish and Undo posts from the owner port |
| Restore upload to the server | Untrusted file content |
| Release to state directory | A new release reads and rewrites data an older release wrote |
