# Phase 06.1 Plan 14: Lit cubbies - Always on, fading in gently once per tab, never over a box Summary

With the lights stored as Always on, every cubby is lit by a hidden warm strip lamp that fades in over 2 s after the first paint, once per browser tab, never paints over a box face, glows on the floor on woods that have one, washes the shelf top in Deep, and every spine tone keeps 4.5:1 in all nine light and depth cases.

## What was built

- **Lights (`cabinet-modifiers.css`):** the light layer is `display: block` for `on` and `evenings`, `opacity` 0 until `data-lit`, with `transition: opacity var(--lamp-fade)` only under `data-settled`; `--lamp-fade` is 2000ms and 0ms under reduced motion; `will-change: opacity` only under `data-fading`; `--lamp-front` is declared 0. `[data-lit] { --keyline: var(--keyline-lit, 0.4) }` switches the box keyline with no transition.
- **The lamp:** each `light-pool` paints the source line (`max(2px, 2.5u)` at 0.8 in `--lamp-hot-rgb`), the birch warm fill (`0.25 x --fill-k x --depth-k` to 14 %), and `radial-gradient(ellipse 200% 50% at 50% 0%, ...)` with the Critic's stops at `--pool-k`. `::before` is the faint spill on the upright and shelf front (0.08 x `--lamp-k`). In Deep, `::after` lights the shelf top (highlight hairline plus 0.32 x `--lamp-k` over its top 32 %). `.section-light::before` is the floor glow in front of the base (0.14 x `--lamp-k` x `--room-k`, so nothing on brown). There is no skirting wash.
- **`look.js`:** `initLook(doc)` waits for the cabinet to be drawn and two frames, then in one task sets `data-settled`, `data-fading` and `data-lit` (fade), writes the tab flag in a `try`, and removes `data-fading` on the opacity `transitionend` or shortly after the fade length. A page the head script already lit only settles. Exports `refreshLamp(root)` and the pure `isLit(lights, evening)`.
- **`evening.js`:** classic script in an IIFE; with the stored lights not off and the tab flag set it sets `data-lit` before the first paint; exposes only `window.cabinetEvening` (`key`, `markLit`). About 1.5 KB with docs, no `//`, no import or export.
- **`_Layout.cshtml`:** `evening.js` is a synchronous head script only when the stored lights are not off; the meta `cabinet-evening-script` always carries the versioned address.
- **Tests:** `LightsTests` (fade after first paint, face pixels identical off and on, once per tab, storage that throws, head script rules and no CSP violation, oak floor glow versus brown none and containment, Deep shelf top, box-top edges on the 400 sample for 7 backs x Classic and Modern); `ReducedMotionTests` (instant lights, `0s` transition); `LookContainmentTests` now runs every design with the lights off and on; `LookSpineContrastTests` (108 cases, the lamp-front and shade caps, the pool strengths, and 7 visibility-floor rows); `look-lamp.test.mjs` (19 node checks of both scripts); the page-scripts style test lists `look.js` and `evening.js`.

## Deviations from Plan

Where the plan text and the Round outcome or the approved mock sources disagree, the latter were followed.

### Round outcome over plan text

**1. [Round outcome] Lamp shape, source line and strengths**
- The plan described a 90 % wide ellipse at 0.55 down to 12 %, a separate hairline at 0.55 of `max(1px, 1.5u)`, and `--lamp-k` for everything. The Round outcome (and the mock's `modifiers.css`) fixes the hidden strip: ellipse 200 % x 50 % with the Critic's stops at `--pool-k`, the visible source line `max(2px, 2.5u)` at 0.8 in `--lamp-hot-rgb`, birch's warm fill `--fill-k`, and no separate band. Built as the Round outcome says.
- **Files:** `cabinet-modifiers.css`. **Commit:** dc1e96f

**2. [Round outcome] No skirting wash**
- The plan's floor glow and skirting wash (0.10) became only the floor glow in front of the base; the wash was removed.
- **Files:** `cabinet-modifiers.css`. **Commit:** e394168

**3. [Round outcome] Visibility floor uses `--pool-k` and recomputed accepted values**
- The plan read the peak and tail from `--lamp-k`; the pool is painted with `--pool-k` (birch 0.12, painted backs 1), so the test uses it. The accepted values in the UI-SPEC table were computed for the earlier backs (walnut `#301e15`, oak `#2b2117`) and the older lamp, so the test records the values recomputed from the shipped tokens (bare / peak / tail): brown 1.66 / 1.43 / 1.49, walnut 1.71 / 1.41 / 1.53, oak 1.70 / 1.42 / 1.53, birch 1.49 / 1.39 / 1.49, mahogany 1.85 / 1.50 / 1.67, painted 1.66 / 1.42 / 1.49, each allowed to drop 0.02 and none under 1.3.
- **Files:** `LookSpineContrastTests.cs`. **Commit:** 3ce02be

### Auto-fixed issues

**4. [Rule 1 - Bug] `initLook` must wait for the drawn cabinet**
- **Found during:** Task 1
- **Issue:** the module runs before the layout is fetched, so a fade started "two frames after load" would end before any light layer existed and the visitor would never see it.
- **Fix:** `initLook` waits for the `cabinet:drawn` event (or an existing light layer), then two frames; a redraw later swaps in new light layers that are already lit and need no fade.
- **Files modified:** `look.js`. **Commit:** dc1e96f

**5. [Rule 3 - Blocking] The page-script fake page lacked what `initLook` reads**
- **Found during:** Task 1 (node tests)
- **Fix:** the fake document gained `documentElement`, elements gained `hasAttribute`, and the fake window `requestAnimationFrame`.
- **Files modified:** `build/tests/page-scripts.test.mjs`. **Commit:** dc1e96f

**6. [Rule 1 - Bug] The containment reading broke on a hidden light layer**
- **Found during:** full browser suite
- **Issue:** with the new floor glow pseudo-element, `getComputedStyle(element, '::before')` of the `display: none` light layer reports content but an unresolved `top`, so the reading had a null number (7 cases failed).
- **Fix:** the reading skips pseudo-elements of an element that is not displayed; the theory now runs every design with the lights off and on, so the glow and the shelf top wash are proven inside the section box.
- **Files modified:** `LookContainmentTests.cs`. **Commit:** 019cef6

### Interpretation notes

- `data-settled` is set after the first draw whatever the stored lights are (it only enables the fade, and the light layer is `display: none` while off), so a later live switch to a lit state fades.
- The meta tag uses `IFileVersionProvider` (a `?v=` address) as the plan says, while the tag helper on the head script emits the fingerprinted static asset address; both serve the same file.
- `evening.js` exposes `markLit(root)` (sets `data-lit` from the attributes) for the evening clock and the live switch; the head script itself uses it for the once-per-tab case.
- Evenings only never lights from the head script yet: there is no evening marker until the clock is added.
