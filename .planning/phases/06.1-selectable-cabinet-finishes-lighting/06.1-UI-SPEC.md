## Structure that does not depend on taste (FIXED)

### The five root attributes

Written by the server on `<html>` of **every page that shows a cabinet**: the public cabinet on both ports, including the cabinet at the owner address. Owner pages that show no cabinet (Pictures, Locations, Settings outside the preview) carry **none**, so they keep today's look (D-19). The Settings preview wrapper carries the same five attributes with the trial values.

| Attribute | Allowed values | Default | Stored value (same string) |
|-----------|----------------|---------|----------------------------|
| `data-design` | `classic`, `modern`, `display`, `legs`, `library`, `plywood`, `plywood-legs` | `classic` | yes |
| `data-wood` | `brown`, `walnut`, `oak`, `birch`, `mahogany` | `brown` | yes |
| `data-backs` | `wood`, `painted` | `wood` | yes |
| `data-lights` | `off`, `on`, `evenings` | `off` | yes |
| `data-depth` | `flat`, `shaded`, `deep` | `shaded` | yes |

- The attribute value and the stored owner-data value are the same string, from **one allow-list per field** on the server. A value that is not on its allow-list falls back to that field's default **alone** (an unknown design never resets the wood). A file from before this phase (`finish: "classic"`) restores as the five defaults.
- The tile names on the settings page are display names only: `Plywood on legs` is `plywood-legs`, `On legs` is `legs`, `Warm brown` is `brown`.

**Derived markers (script, never stored):**

| Attribute | Set by | Meaning |
|-----------|--------|---------|
| `data-evening` | `evening.js` in `<head>`, **before the first paint** (whenever `data-lights` is not `off`); kept current by `look.js` | Present from 30 minutes before sunset until sunrise by the visitor's clock. Only meaningful when `data-lights="evenings"` |
| `data-lit` | First load in a tab: `look.js`, **after** the first paint (two animation frames), so the lights fade on. Later loads in the same tab: `evening.js`, **before** the first paint, so the lights are already on (see "Lights", once per tab) | Present when the lights are on: `lights=on`, or `lights=evenings` with `data-evening` present |
| `data-settled` | `look.js`, in the same task as the first `data-lit` it sets (or after the first paint when `evening.js` already set it) | Enables transitions. Before it exists nothing animates, so the first frame is exactly the server's markup plus the head script's markers |

### The four CSS layers and what each may touch (D-04)

Declared once, as the **first rule of the first stylesheet** the layout links: `@layer structure, design, wood, modifiers;`. Every cabinet rule lives in a layer. **An unlayered cabinet rule is forbidden**, because unlayered rules beat all layers (a CSS test fails on one).

| Layer | May set | May not set |
|-------|---------|-------------|
| `structure` | Positions, sizes and stacking from custom properties; the reserved `aspect-ratio`; `content-visibility`; hooks; z-index map; the geometry of the focus ring and the halo (outline width and offset, the 6 px halo spread) and of the wall shadow, all reading their colours and strengths from tokens | Any colour literal; any look chosen per design or wood |
| `design` | Every **size** in millimetres: top, base, legs, side trim, overhang, base inset, floor margin, corner radius, plank width, ply period, inlay width, depth inset; the recipe of each member (which gradient layers, in which order); the section's reserved height | Any colour literal. A design reads colours only through wood tokens |
| `wood` | Colours and unitless strengths only, as custom properties: board, edge, grain, back, cubby walls, recess, inlay, keyline, ring, ring halo, wall shadow, lamp strength, and the room tokens | Any length, position, size, `aspect-ratio`, `display` or `content-visibility` |
| `modifiers` | Overlays and their strengths: depth (flat, shaded, deep), lights (the light layer), painted backs (the back colour and no seams), evening (dusk) | Any layout-affecting size. Anything on a box face except the shade alpha caps in "Contrast and test contract" |

**Rules (FIXED):**

1. **No pair selectors.** No rule may combine two choices, such as `[data-design="library"][data-wood="birch"]`. A pair that reads badly is fixed with a token. A pair exception needs the owner's approval in the round (listed as R-9).
2. **The wood layer is the only place a colour literal may be written** (plus neutral lighting overlays `rgb(0 0 0 / a)` and `rgb(255 255 255 / a)` in structure and modifiers). Every other layer reads `var(--...)`.
   - **Light colours are wood-layer tokens too.** The lamp `--lamp-rgb`, the wall falloff `--falloff-rgb`, the dusk `--dusk-rgb`, the warm highlight `--highlight-rgb` and the plank lift `--plank-lift-rgb` are declared once in the wood layer's base block (shared by every wood, overridable per wood) as channel triplets, and used as `rgb(var(--lamp-rgb) / a)` and so on.
   - **The design layer has no literal at all.** Its shadows (contact spots, floor ellipses, the kick shade, the Display float shadow) are `rgb(var(--shade-rgb) / a)`, tinted by the wood rather than pure black; its highlights are `rgb(var(--highlight-rgb) / a)`; its alphas are plain numbers.
   - **Today's classic block moves its tints into tokens with identical values.** It writes five literal tints today: `20 10 4` (shade), `10 5 2` (deep shade), `255 240 220` (lit arris), `255 245 230` (board sheen) and `255 235 210` (plank lift). The split moves each into a wood-layer token with exactly that value (`--shade-rgb`, `--shade-deep-rgb`, `--arris-light-rgb`, `--sheen-rgb`, `--plank-lift-rgb`) and keeps every alpha, so the frozen default stays pixel-identical (proved by the default-identity test).
3. **Only the design layer changes the section's size.** Changing wood, lights, depth or backs never moves, resizes or clips anything. A browser test compares every section's bounding box across all 5 × 2 × 3 × 3 combinations of the other four choices for each design and requires the boxes to be identical.
4. **No attribute, no problem.** An element with none of the five attributes (a test page, an owner page's own mini shelf) must render as the default look. The default values therefore live in the layers as the base case, and every other value overrides them.
5. **The preview works on a wrapper.** Every attribute selector is written as `[data-design="x"] .cabinet` or `[data-wood="x"]` with the attribute on any ancestor, never `:root[data-design="x"]`, so the same CSS drives the page and the preview.
6. **Tokens, not literals, are the interface.** The vocabulary is listed in "Starting values".

Only a new option may add to it. The proof is the first test written (see "Verification contract") and is run before and after the CSS split.

The frozen values are today's block in `cabinet.css`. They become the **classic design** and **warm brown wood** and must not be edited:

### Renderer hooks, stacking and paint containment

**Hooks.** The renderer stays attribute-agnostic: it never reads the look. It adds decoration through `buildDecoration`, as it does for top, trim and base.

| Hook | Where | Status | Note |
|------|-------|--------|------|
| `section-top`, `section-trim`, `section-base` | per section | existing | unchanged |
| `section-light` | per section, after `section-base`, `aria-hidden="true"` | **FIXED, new** | Holds all the light of the section (D-11). Positioned exactly like `.section-body`. Only its `opacity` animates. One compositor layer per section |
| `light-pool` | one child of `section-light` per cubby, `aria-hidden`, positioned by the cubby's own `--x --y --w --h` | **FIXED** (see note) | The renderer can only draw a pool where it knows a cubby is. Children are static (no animation); they cost one empty node per cubby. A generated multi-gradient is the alternative and is a build choice, not a contract change, as long as only the one parent animates |
| `section-floor` | per section, `aria-hidden`, behind the body | **ROUND** (R-3, only if the floor patch per piece wins) | Draws the skirting and the floor patch inside the section box |
| `data-position` on a section (`first`, `middle`, `last`, `only`) | phone profile only | **ROUND** (R-1, only if sections are joined for any design) | Lets the design layer draw a top only on the first section and a base only on the last |
| `cubby-deco` | optional per cubby, `aria-hidden` | allowed | Only if Deep cannot be drawn with the cubby's two pseudo-elements and its backgrounds. The summary must state the node count it adds |

**Stacking map (FIXED).** Everything inside a section shares one stacking context (the section itself, through `content-visibility`). `.cubby` and `.section-body` must **not** create a stacking context (no `z-index`, `opacity`, `transform`, `contain` or `isolation` on them), or the light layer cannot slot between the back and the boxes.

| Level | What | Why |
|-------|------|-----|
| −1 | `section-floor` (if built) | Behind the body |
| 0 (auto, tree order) | Section body, cubby backs, shelf boards, `section-top`, `section-trim`, `section-base` | The furniture |
| 1 | `section-light` (dusk shade, pools, lit shelf edge, floor glow) | **Under the boxes**: lights the back, the shelves and the uprights, never a box face |
| 2 | `.placement` (every box) | Boxes stand in front of the light |
| 3 | `.cubby::after` (shade over boxes, today's shade) | The only layer above a box face, as today |
| 4 | `.placement:focus-visible` and `.placement[data-open]` | The ring always paints above everything |

Relative order is exactly today's (shade above boxes, focus above shade). **Why the light is under the boxes:** a lamp tint laid over a box lifts the background and the white label text together and lowers their ratio. With the 20 % shade already on, **Rust has 4.51:1 and Teal 4.67:1 and there is no headroom** (computed). Putting the light under the box makes the light × depth contrast test hold by construction and keeps box colours true.

**Paint containment (FIXED, D-16, D-28).** `.section` keeps `content-visibility: auto`, so everything a design draws (crown, legs, base, floor patch, glow, shadows, the dusk shade) must **end inside the section box**. The section's reserved height is `top + section-h + base + floor margin` and comes from the design layer's `aspect-ratio`, so nothing shifts while loading. A browser test checks, for every design × wood, that the one-pixel ring at the edge of each section's box is the wall colour (no clipped shadow tint) and that every decoration's rectangle lies inside the section's rectangle. A shadow that ends in a straight hard line is a defect.

### Depth (D-07, FIXED structure)

| State | What is drawn | Shade over boxes (`--shade-alpha`) |
|-------|---------------|------------------------------------|
| `flat` | No shading at all: no shadow under the shelf above, no side shade, an evenly lit back. The design's back construction stays (Classic keeps its planks and their seams, D-07), and so do grain and lit edges on the furniture (they are material, not shading) | 0 |
| `shaded` | Today's look: the shelf above's shadow on the back, side shade, plank seams, and the shade over boxes. **Default** | **0.20 (frozen)** |
| `deep` | `shaded`, plus: inner side walls, a top face and a floor in perspective (an inset of `--depth-inset` mm), and a thin lit top face on every shelf board (`--top-face` mm). Display's "seen slightly from above" view lives here | 0.12 (START, never above 0.20) |

No design carries depth of its own. The planked back of Classic and the plain sheet of Plywood are **back construction** (design layer), not depth.

### Lights (D-08 to D-12, FIXED structure)

- Three states: `off`, `on`, `evenings`. `evenings` is lit when `data-evening` is present.
- **Fade:** `.section-light` has `opacity: 0` unlit and `1` lit. `transition: opacity var(--lamp-fade) ease-in-out` is declared only under `[data-settled]`, so the first frame has no transition. `--lamp-fade` is 2000ms (START, "about 2 s"). **Reduced motion: `--lamp-fade` is 0** and the switch is instant.
- **Once per tab (owner choice, review T2):** the lights fade on after the first paint on the **first page load in a browser tab**. Later loads in the same tab (a language switch, the owner moving between pages) start with the lights already on, with no fade. The rule:
  - `evening.js` runs in `<head>` before the first paint whenever `data-lights` is not `off`. It sets `data-evening`, then reads one `sessionStorage` flag (a fixed key, value `1`, nothing personal). If the flag is set and the lights are lit, it sets `data-lit` at once, so the first frame is already lit.
  - Otherwise `look.js` sets `data-lit` after the first paint (the fade), and writes the flag when that fade starts.
  - If `sessionStorage` is unavailable (an exception is thrown), the page fades on every load, which is the safe fallback.
  - A page left open across sunset or sunrise always fades, whatever the flag.
- When `data-lights="off"` the layer is `display: none` (no cost, no trace). Switching from `off` to a lit state sets `display` first and `data-lit` one frame later so the fade starts from 0.
- **The light never paints above a box face** (stacking map). The front-of-box lamp alpha is the token `--lamp-front`, **FIXED at 0**. If the round wants a lift, the budget that keeps every palette tone at 4.5:1 with the depth shade stacked is (computed):

  | Depth | Shade alpha | Largest `--lamp-front` that passes |
  |-------|-------------|------------------------------------|
  | flat | 0 | 0.08 (Rust limits it at 9 %) |
  | deep | 0.12 | 0.04 |
  | shaded | 0.20 | 0 |

  Raising it above the table is not allowed. This is also what the nine-case spine test enforces.
- **Reading of D-12, accepted by the owner (review S8):** "only slightly lifts box fronts" is built as **no lift**. A strip light aimed at the back panel leaves the box fronts in the shelf's shade, so the boxes read as backlit; and under the default Shaded depth there is no contrast to spare. A lift on **Flat only** (at most 0.08) stays a round option.
- **The pool is a strong, short strip-light band (review U1, FIXED shape, START numbers).** A soft, mid-strength pool lifts a dark back right onto the seven dark spine tones, so the dark boxes vanish into the glow at box-top height. Computed with the earlier soft pool (0.34 peak): brown back 1.20:1 against the weakest box, walnut 1.10, mahogany 1.21, petrol 1.01, against today's 1.66. A strong peak in the clearance above the boxes that falls off fast crosses the dark band only in a thin ring, and reads like a real LED strip (a bright band near the source, a quick falloff) rather than a vignette. Values in "The lamp".
- **Evening (D-09), FIXED rules:** lit from **30 minutes before sunset** to **sunrise**, by the visitor's own clock, from one fixed table of local clock times (summer time already applied), a few points per month, interpolated by day of year. No location is read. The table is `evening.js`'s only data. The page checks the clock on load, every 60 seconds while visible, and on `visibilitychange`; a page left open across either moment fades the same way.
- **START for the table** (planner owns the numbers): latitude 52° N; three points a month (the 1st, 11th and 21st); extra points on each side of the two summer-time changes so interpolation never runs across a one-hour step; a unit test compares every point with the standard solar formula within 5 minutes. A visitor in another time zone gets the table's clock times. This is accepted for the owner's audience (listed in "UI Considerations").
- **`evening.js` is a classic script, one copy of the table.** It is loaded in `<head>` synchronously (no `defer`, no `type=module`) whenever `data-lights` is not `off`, because both the once-per-tab rule and room dimming (if the round chooses it) need its markers before the first paint. With lights `off` it is not loaded. Under the CSP it is a file. Target size 1 KB.

### The room (D-02, D-15, D-17 to D-19, FIXED structure)

The wall is **painted on the canvas** (the `body` background propagates to the canvas as today), and the soft falloff is painted on `body` as a top-anchored, `no-repeat`, `100% 100lvh` background that scrolls with the page (owner, second round S-1: there is no fixed full-viewport layer, no `html::before` and never `background-attachment: fixed`; `html` has no background; the large viewport height never changes when a phone's address bar collapses). The dusk dim does not exist (lights only). **Final: see Round outcome.** Wall and floor tokens come from the wood layer; a wrapper (the preview) paints its own room with the same tokens.

**Wall shadow (review S7, FIXED structure, START strengths).** A real cabinet stands a few centimetres in front of the wall and casts a soft shadow onto it. That is what separates a pale piece from a pale wall (birch on plaster is only 1.14:1). The structure layer draws it as a background of the section box itself (behind every hook, so it never touches the furniture or a box): a soft band down the right side of the piece and a thinner one under the top's overhang, inside the side allowance (at least 4 mm free on every design, 32 mm on Plywood), in `rgb(var(--shade-rgb) / var(--wall-shadow))`. The wood layer sets only `--wall-shadow`: **0 on warm brown (frozen)**, 0 on the other dark walls, 0.22 on birch, 0.15 on any other light wall (the warm-stone walnut wall, if the round picks it).

**New public-chrome tokens (wood layer; names are START, the split is FIXED).** Public chrome (header, status line, sync block, language toggle, games list, footer, the page's own focus rings) reads `--room-text`, `--room-muted`, `--room-line`, `--room-ring`, `--room-accent` with a fallback to today's `--wall-text`, `--chrome-muted`, `--chrome-line`, `--wood-light`. **The owner strip, plate, bar and dock keep today's tokens** (`--wall-text` on `--wood-mid`, 6.8:1): the owner contrast tests assume light text on mid wood, and a light wall would otherwise flip that text to dark. **The owner banner is a paper strip** (`--paper` fill, `--ink` text, `--paper-edge` border, the ink focus ring, as built in `owner.css`) and keeps those paper tokens on every wall; this supersedes the "banner button on wood" wording in `06-UI-SPEC.md`. The card and its paper tokens are unchanged (D-19).

**Logo:** the server renders the variant for the stored wood: white on dark walls, the dark navy `#3F3A60` logo on the light wall. The live switch and the preview swap `src` between the two files (same size 342 × 76, same alt, same link). **Rule:** dark logo when the wall's relative luminance is above **0.27**, white at or below it (the two logos have equal contrast at 0.273, computed). Keep every wall **below 0.12 or above 0.45** so the choice is never marginal.

## Design lens: the cue list

The reference is **a real wooden cabinet of games, in a room**. The earlier plain look came from five missing cues: board thickness, grain, depth in the cubbies, furniture parts, and bare cubbies reading as black holes (02-UI-SPEC). The cues below say what makes each build read as real. They explain why the values in "Starting values" are what they are.

**One light, always:** soft, from above and slightly left. Top and left edges are lit, undersides and right edges are darker, shadows fall down and slightly right and are **tinted** (`--shade-rgb`), never pure black. The lamp is a second light that obeys the same rules.

### Designs

| Design | What makes it read as real | Weak point and how it is handled |
|--------|----------------------------|----------------------------------|
| **Classic** (today) | A moulded top that overhangs thicker side boards; grain along every board and a tone per shelf; planked tongue-and-groove back; a plinth with an arch between two feet; a soft floor shadow | Frozen. Nothing to handle |

## Contrast and test contract (D-26, D-27, FIXED)

Contrast is computed, never judged by eye. All tests read the tokens from the shipped CSS (the way `OwnerContrastTests` does) and blend on gamma-encoded channels the way the browser does.

**Test 1: spine contrast under what can fall on a box (R3).** For each of the 12 palette tones, in each of nine cases (lights `off`, `on`, `evenings` evaluated lit, times depth `flat`, `shaded`, `deep`), the background and text, both blended with the depth shade at its `--shade-alpha` **and** the lamp at `--lamp-front`, must stay at or above **4.5:1**. It also asserts `--lamp-front` is within the budget table and that the shade alphas are within the existing 20 % cap (`SpinePalette.MaxShadePercent`). Wood and design never touch a box face, so they are not in the matrix. Computed baselines: no overlay, the tightest tones are Rust 5.28 and Teal 5.44; under the shaded 20 %, Rust 4.51 and Teal 4.67.

**Test 2: chrome contrast per wall (R3).** For each of the five woods, in **day and evening** (the wall blended with the falloff at its brightest and, in evening, with the dusk dim):

- `--room-text` on the wall at least 4.5:1; `--room-muted` at least 4.5:1; `--room-line` at least 3:1.
- The footer and status line text, the sync button text and its border, and the language toggle follow from those three.
- The chosen logo's own colour (white or `#3F3A60`) at least 4.5:1 on the wall, and the choice matches the 0.27 luminance rule.

**Test 3: focus rings.** For each wood, **and** for each of its surfaces (frame, plain back, painted back, shelf, wall), the ring pair (accent inside, ink halo where the wood defines one) must have at least one colour at **3:1 or more** against the surface. Computed minimum across all: oak back 8.45 (accent), oak frame 7.2 (ink), birch frame 10.2 and back 4.99 (ink), painted back 8.98 (accent). The wall ring (`--room-ring`) must reach 3:1 on its wall.

**Test 4: tag tones.** The accent chip's ink text (8.98:1) and the corner tag's two tones keep their earlier tests, which do not change.

**Visibility floor (round check, not a pass or fail test).** Box against back panel, measured **three ways**: on the bare back, at the lamp pool's peak, and in its tail (review U1). Today's weakest tone on today's back is Navy 1.66:1. Computed weakest tones with the backs in this contract:

### Trial, publish, discard (D-20)

- Every tap changes only the **trial**: the preview, the tiles and the summary update at once; **nothing changes for visitors**.
- The line **Visitors see** always shows the current look; the line **Trying** appears only when the trial differs (see copy). Both are plain text.
- **Use for everyone** (primary on paper) posts all five values in one form post, with the page revision (the existing stale-page rule). **Back to current** (secondary) restores the trial to the current look. Both are `aria-disabled` (dashed border, `--paper-label` text, no hover) while the trial equals the current look.
- A successful publish: the row status reads **Saved for everyone** with **Undo** (the Phase 6 model: reverts only the latest change, no timer), the **Visitors see** line updates, the change log gets one entry, and open pages follow.
- A failed save: `Couldn't save that. Nothing changed. Try again.` The trial stays. An out-of-date page and an expired form use the existing Phase 6 messages with **Reload**.
- The trial is page state only. Leaving the page drops it. A reload shows the current look.
- **Without script:** the tiles still draw (CSS only), the form still posts with its radios and checkbox through a visible **Use for everyone** button, and a note says the preview needs scripts.
- Focus: after a tap focus stays on the control. After **Use for everyone** it stays on that button; after **Back to current** it moves to the first checked design radio. Status text is in the polite `role="status"` line.

## Live switch (D-23, D-24)

After **Use for everyone**, an open public page applies the new look within **about 5 seconds** through the existing live channel (the planner chooses the message or a version bump).

1. **Equal look:** do nothing.
2. **Reduced motion:** apply the attributes at once; no transition.
3. **Only the lights changed:** apply the attributes; the 2 s lamp fade runs by itself. No page cross-fade. If the page was opened with the lights `off`, `evening.js` is not loaded yet, so `look.js` first adds it as a script element and applies the look once it has run.
4. **Anything else changed:** apply inside `document.startViewTransition()` where it exists (a short root cross-fade, `--look-fade` 250ms START), otherwise apply at once. The page never flashes empty.
5. **A design change keeps the visitor's place (R9):** before applying, record the section that holds the viewport's vertical centre and its distance from the viewport top; after applying (inside the transition callback) scroll by the difference so that section is where it was. Changing wood, lights, depth or backs moves nothing (rule 3), so only a design change needs this. **One scroll keeper, not two (review S3):** Chrome and Firefox already anchor the scroll position natively (`overflow-anchor`), Safari does not; so the page sets `overflow-anchor: none` on the scrolling element while a design change is applied and restores it afterwards, and only this rule moves the page.
6. **An open game card stays open.** The card is in the top layer and is not rebuilt. **A look change that arrives while a pull-out animation is running is applied after the animation ends** (FIXED rule), so a box never jumps mid-flight; the 5-second window is measured from when the animation ends in that case.
7. The footer logo `src` swaps when the wall tone changes between light and dark.
8. If the live channel is down the page follows on its next load; nothing breaks.

## Verification contract

**Unit tests (xunit.v3, FluentAssertions, `FakeTimeProvider` for time):**

3. **Paint containment.** For every design × wood: the one-pixel ring at each section box edge equals the wall colour (no clipped tint) and every decoration lies inside the section rectangle.

## Assumptions Carried to the Planner

1. **Server.** The layout writes the five attributes on `<html>` on both ports for every page that shows a cabinet, and none on the owner pages without a cabinet. The `finish-*` body class is removed together with its tests. The footer renders the logo variant for the stored wood.
2. **Stored data.** The five values replace `Finishes.Allowed` and `OwnerData.Finish`; the schema version rises; the previous release cannot read a file saved by this one, so a rollback after publishing falls back to an earlier copy or the default look. The planner states the rollback behaviour in the plan.
3. **CSS.** The four layers replace the single finish block. Existing public chrome rules move to the `--room-*` tokens with today's tokens as fallbacks; the owner chrome, the owner banner (paper) and the card keep today's tokens. Today's `.cubby::after` shade z-index changes from 1 to 3 and `.placement` becomes 2 and its focus and open states 4, preserving today's relative order. The design layer exposes `--section-ratio` (the unitless ratio behind the section's `aspect-ratio`) for the settings preview. The wall shadow is a background of the section box itself.
4. **Renderer.** `buildSection` appends `section-light` after `section-base` and one `light-pool` per cubby; `section-floor`, `data-position` and `cubby-deco` only if the round needs them.
5. **Round first.** No production code is written until the owner approves the round. Default identity (test 1) is written before the CSS split.
6. **Layout order.** Compare classic before and after the split on the same layout version; balancing the desktop sections (separate decision) changes section contents afterwards, so the round's sheets are re-shot once after balancing.
7. **Check link and balancing** are not visual work and appear here only as screenshot context.
8. **Head script.** `evening.js` is linked synchronously in `<head>` on every cabinet page whose stored lights are not `off` (it carries the clock table and the once-per-tab rule), and not at all when they are `off`. When a live switch turns the lights on in an open page, `look.js` adds the same file as a script element (allowed under `'self'`) before applying the look.
