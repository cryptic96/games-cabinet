# Plan 07-24: The screen-reader list follows the view and the filters

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 7`): "A visitor can narrow the cabinet to tonight's game by dimming everything else, and can switch between one big cabinet and one cabinet per storage location."

Coverage note: no SPEC; spec-less probe fallback ran (see plan 07-01). This plan lifts UI E7 empty, partial, zero-one-many, loading, error and overflow (E7 populated is checked in the device round, plan 07-34).

<objective>
Make the accessible games list carry everything the cabinet now shows (D-22): each entry's location, only the matches while filtering, and one group per location in By location, with the list's entries always equal to the bar's count (D-07). The list reads the same entries the count uses, from the `cabinet:filtered` event, so the two cannot disagree.

Purpose: a screen-reader user gets the same answer a sighted visitor sees in the light.
Output: the extended `games-list.js`, node tests, `FilterListTests`.
</objective>
