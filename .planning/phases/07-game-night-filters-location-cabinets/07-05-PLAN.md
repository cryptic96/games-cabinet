# Plan 07-05: The BGG access check counts edition names and other titles, without recording them

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 7`): "A visitor can narrow the cabinet to tonight's game by dimming everything else, and can switch between one big cabinet and one cabinet per storage location."

Coverage note: no SPEC; spec-less probe fallback ran (see plan 07-01). This plan lifts no probe edge.

**Owner approval:** this plan is N1 in `07-RESEARCH-QUESTIONS.md` ("Check BGG's real data shapes without recording them"), which the owner accepted on 2026-10-15 together with Q1 to Q3: the repository has never stored a real BGG answer and must not, so the plans build tolerant readers (plan 07-04) and extend the existing server-side access check to report counts only.

<objective>
Extend the existing BGG access check so its next real run on the server tells the owner how often BGG's answers carry an edition name on the selected version and how many alternate names games carry, as counts only (N1). This is how the real shapes behind the tolerant readers of plan 07-04 get confirmed without a single real answer entering the repository.

This is a support plan: it delivers no visitor or owner feature itself. It maps FILT-01 and LOC-05 only because it verifies, with counts only, the two plan 07-04 readers those requirements depend on (the alternate names behind the title search, and the edition names behind the per-copy labels the location work shows); the requirements themselves are delivered and tested by the plans that use those readers.

Purpose: the readers' assumptions are checked against BGG on the owner's server, and nothing personal or recorded is committed.
Output: the new counts, their leak checks, the offline test and the guide lines.
</objective>
