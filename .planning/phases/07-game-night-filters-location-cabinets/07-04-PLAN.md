# Plan 07-04: The sync keeps BGG's other titles and the owned edition's name

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 7`): "A visitor can narrow the cabinet to tonight's game by dimming everything else, and can switch between one big cabinet and one cabinet per storage location."

Coverage note: no SPEC; spec-less probe fallback ran (see plan 07-01). This plan lifts no probe edge. It reads two more fields from BGG calls the sync already makes; visitors never trigger a BGG call (the browser-facing prohibitions live in plan 07-19, where the names reach the page).

<objective>
Read BGG's alternate names from the details call (D-14) and the owned edition's name from the collection call with `version=1` (D-31), keep both in the snapshot as additive members, and make sure a change of either alone is saved and, for alternate names, published. These are the data both later features read: the alternate-title search (plan 07-19) and the per-copy row labels on the owner pages (plans 07-12 and 07-16). Both readers are tolerant because the real element shapes are recorded only as counts by the access check (plan 07-05).

Purpose: the sync holds every name the phase needs without a single extra BGG call.
Output: `GameDetails.AlternateNames` with details version 2, `SnapshotItem.VersionName`, fake-BGG alternate names, parser, snapshot and sync tests.
</objective>
