# Plan 07-14: One cabinet per storage location, built and cached on the server

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 7`): "A visitor can narrow the cabinet to tonight's game by dimming everything else, and can switch between one big cabinet and one cabinet per storage location."

Coverage note: no SPEC; spec-less probe fallback ran (see plan 07-01). This plan lifts LOC-05 boundary, precision, idempotency and concurrency, UI E5 empty and partial, and the by-location relaying prohibition.

<objective>
Build the server half of the second phase goal: a pure per-location run of the existing layout engine (D-25, D-26, D-24 by re-pairing expansions per subset), cached with the immutable collection state per version and profile, served at `/cabinet/layout-by-location` with the same endpoint hygiene as the layout, and explained in the layout guide. The page's view switch, grouped draw and headings follow in plan 07-22.

Purpose: each place becomes its own stable piece of furniture, computed once per collection change on the low-power host.
Output: `LocationLayouts`, `LocationLayoutsFor`, `LayoutCache.GetByLocation`, the endpoint, engine and endpoint tests, the guide section.
</objective>
