## The three issues that hurt the impression most

1. **The "found" box (Show on shelf) and the reduced-motion open box are marked in the wall's text colour, so on Walnut the mark disappears.** `.placement[data-open], .placement[data-found]` draw `outline: 2px solid var(--room-text)` (cabinet.css). The box sits on the cabinet back, not on the wall. Walnut pairs a light wall (dark `--room-text`) with a dark wood back, so the outline is dark on dark and the jump lands on a box with no visible mark (`M7-show-on-shelf-outline-found-walnut-lit-1440-en.png`, against Brown in `M7-show-on-shelf-found-brown-day-1440-en.png`). Keyboard focus on a box already solved this: it uses `--wood-light` plus the `--ring-halo` ink halo because "the ring has to read against the furniture and not against the wall". Fix: give `[data-open]` and `[data-found]` the furniture ring too, `outline: 3px solid var(--wood-light); outline-offset: 2px;` with the existing `0 0 0 6px var(--ring-halo)` halo (3px keeps it distinct from the 2px focus ring), and add the found mark to the box-ring contrast test on all five woods, day and evening. The "room's text colour" choice in the rule's comment predates Show on shelf; if the UI contract tags it FIXED, explain it in the document as a defect waiting for the owner's yes instead of changing it.
2. **On a phone, with a filter on, the search hint is cut mid-word.** In compact mode the status group narrows the search (U1), and at 390 px the field is about 115 px wide, so the placeholder reads "Search gar" and "Zoek eer" (`M5-sheet-open-*`, `M5-sheet-zero-*`, `M9-owner-filtering-brown-day-390-en.png`, `M12-filtered-forced-day-390-en.png`). A word cut in half looks like a rendering bug. Fix inside the contract's CSS (the placeholder text and the 16px size are fixed): in compact mode while a filter is active and the field is empty, end the hint cleanly instead of clipping it, `.filter-q { text-overflow: ellipsis; }` and `.filter-q::placeholder { text-overflow: ellipsis; }`, so it reads "Search ga…"; or, better, take the hint out of the narrow field in that one state (`.filter-bar[data-compact][data-active] .filter-q::placeholder { color: transparent; }`) and show a 16px magnifier glyph at the field's start from a self-hosted SVG (allowed under `default-src 'self'`), so the field still says what it is. Check both languages at 320, 360 and 390 under the CI font. If neither fits the contract, list it for the owner with the copy option (a shorter compact hint such as "Search", "Zoek").
3. **By location on a wide screen is one long centred column of small, mostly empty cabinets.** At 1440 px the 65 sample becomes a 5,071 px page: seven location cabinets stacked one per row, each about 630 px wide with ten cubbies, centred on a 1,440 px wall, so more than half of every row is bare wall and a place with one game ("Shelf A · 1 game") shows nine empty cubbies (`M6-by-location-brown-day-1440-en.png`, `M6-columns-*`). A real room would put two small cabinets side by side and would not buy a ten-cubby cabinet for one box. This is not a tuning value: the cabinets are sized by the design width and the groups stack by design. **Taste call for the owner** (see K1), not a fix for this round.

## Taste calls

- **K1, location cabinets on a wide screen.** Today: one cabinet per place, stacked in a single centred column, each the design's full width. Option A (built): keep it, it is calm and every place reads as its own piece. Option B: from about 1,280 px let places whose cabinets fit stand side by side on the wall (wrap, top-aligned, headings above each), and size a small place's cabinet to its games (fewer cubbies). B halves the scrolling on a desktop and reads more like a room, but it is a layout change (server layouts per place plus the page's group flow), so it belongs in a follow-up, not this round. Recommended: keep A for this release, and record B as the next layout improvement.
- **K2, the view cross-fade.** The mid frame shows a double exposure of two different layouts, the big cabinet and the small Cabinet A at once (`M8-cross-fade-mid-*`). At 250 ms it is brief, but it can read as a glitch. Option A (built): cross-fade. Option B: fade through the wall: the old view fades out in the first half and the new one fades in during the second half (`::view-transition-old(cabinet-area) { animation-duration: calc(var(--look-fade) / 2); }` and `::view-transition-new(cabinet-area) { animation-delay: calc(var(--look-fade) / 2); animation-duration: calc(var(--look-fade) / 2); }`), with the same total time and no overlap. Recommended: B.
- **K3, the shadow on Birch.** On the light Birch back a dimmed box goes almost black (1.81 against the back, `M2-players4-time60-family-birch-day-1440-en.png`, `M3-veil-06-s65-birch-day-1440-en.png`), so it reads more as a dark stain than a shadow; on the dark woods 0.6 looks natural. Option A (built): 0.6 on every wood. Option B: 0.5 on Birch only (the light woods), keeping the label floor. Recommended: A unless the owner finds Birch heavy in daily use; it is a one-token change later.
- **K4, the "8+" chip's spoken name (N5).** It is spoken "8 or more players" while it shows "8+". Speech-control users say what they see ("click 8 plus"), and WCAG's label-in-name rule asks that the visible text be part of the name. Recommended, against the draft's recommendation: make the hidden phrase "8+ players" (read as "8 plus players"), so the visible label is inside the name; the other chips already pass ("5" in "5 players").
- **K5, the count changes between the views.** The same filter shows "11 of 52 games" all together and "18 of 61 games" by location (`M2-*`, `M6-heading-filtering-*`), because an expansion stored apart from its base counts on its own in a location cabinet. It follows the contract (the count equals the list), but a visitor who switches views sees the total jump. Option A (built): count what each view draws. Option B: say it in the heading count's hint, or count families in both views. Recommended: A, mention it in the help text if people ask.
- **K6, the doubled scroll offset (N11).** Agree with the draft: leave it unless it looks low in daily use.

## What works (keep it)

- The bar reads as wall chrome: transparent in the flow, and once stuck a wall-coloured fill with a soft shadow and a hairline that arrive together (`M1-stuck-edge-*-crop`). The two designed rows hold their height on every wall in both languages.
- The shadow does what the cues ask: a dimmed box stays solid with a faint lit rim on the dark backs (`M3-crop-dimmed-dark-spine-*`), the lamp lifts the cubby back but never the dimmed boxes (`M3-crop-dimmed-box-in-lit-cubby-brown-lit-1440-en-crop.png`), and the hover peek brings a box back without moving it.
- Location headings read as signs on the wall: centred, the name at 24px with a quiet count, muted when a place has no match.
- Every focus ring now stands 2px outside its control and reads on the dark and light walls (`M11-*`), and forced colours keep lit and dimmed boxes apart (`M12-*`).
- The phone sheet is well built: the keypad grid, live taps over a clear backdrop, the primary button that says what happens, and a zero state that turns into Clear and Close.
