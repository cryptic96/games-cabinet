# Plan 05-01: Browser test harness

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 5`): "A visitor can tap any box, watch it slide out of the shelf, and read everything needed to pick it for game night in English or Dutch, by touch, mouse, keyboard or screen reader."

<objective>
Give the phase a real browser to prove its behaviour in: a new `Cabinet.BrowserTests` project on Playwright .NET, a first end-to-end test of the cabinet page, and a separate CI job. Every later plan of this phase (the card, the pull-out, reduced motion, the keyboard, the games list, the language switch) adds its browser tests here.

Purpose: the phase's success criteria are browser behaviours (animation started or not, focus moves, history steps, tab order); node tests alone cannot prove them. This is the validation strategy's foundation set (the browser project, the CI job and the node test glob).
Output: the browser test project, its lock file, the CI job, the documentation.
</objective>
