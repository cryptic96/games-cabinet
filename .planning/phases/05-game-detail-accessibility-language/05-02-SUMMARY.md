# Phase 5 Plan 02: Card data for every game Summary

**Undocumented `/cabinet/cards` route serving every card and games-list field for the synced collection and the invented samples, with a content-hash ETag, 304 revalidation, and expansions listed on every owned base.**

## Accomplishments

- `CardRecords.Build(items, snapshot, design)` produces one record per item: identity, verbatim title, year and location from the stored entry, box ratio, cover (narrowest stored size at least 384 px on desktop and 224 px on phone, else the widest), colour pair, tone and pattern indices, players, times, age, weight and rating rounded once to one decimal (midpoint away from zero), designers, mechanics, `expansions` and `bases`.
- Zero or negative counts, times and ages are sent as absent; the ranked rating, families, image addresses and enrichment data are never in the record type, and a unit test proves none of them reach the JSON.
- Expansion links are read from the stored details (`ExpandsGames`), never from the layout's single pairing. An expansion of two owned bases appears on both. `bases` lists only owned bases (earliest entry per game, ordered by game id, with chip colour) when any is owned, else the named bases with no entry id and no chip. The ownership rule (a base entry that is also an expansion entry is not an owned base) is copied from the layout pairing, not called.
- `SampleCardDetails.SnapshotFor` gives deterministic invented details: about one base game in ten with no details, one to three designers, up to fourteen mechanics, about half of the entries with an abstract location label, and for the `edge` sample designers and locations in Latin, Cyrillic, Japanese, Thai and Arabic script plus an emoji.
- `CardsEndpoint` mirrors the layout endpoint: profile and sample allowlists, 404 for an unknown profile, `ETag` plus `Cache-Control: no-cache`, 304 on a matching `If-None-Match`, no cross-origin headers, no BGG or image-host request. The document's `layout` equals the layout endpoint's ETag for the same collection and profile.
- `CollectionState.CardsFor` caches the synced cards per design with the collection view, like `LayoutFor`.
