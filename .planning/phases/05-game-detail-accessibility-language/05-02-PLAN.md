# Plan 05-02: Card data for every game

## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 5`): "A visitor can tap any box, watch it slide out of the shelf, and read everything needed to pick it for game night in English or Dutch, by touch, mouse, keyboard or screen reader."

<objective>
Serve every field the detail card and the screen-reader list need from a new undocumented endpoint, `GET /cabinet/cards`, under the same allowlist and ETag rules as the layout endpoint, for both the synced collection and the invented samples (D-09). The data is already in the snapshot (research Summary: no sync change); this plan adds the pure builder, the sample details generator, the cache and the endpoint.

Purpose: the card must never fetch on tap or show a spinner (D-09, R6), and it must list an expansion on every owned base (D-14), which the layout pairing does not.
Output: `CardRecords` (Domain), `SampleCardDetails` (Domain), `CardCache` and `CardsEndpoint` (Service), `CollectionState.CardsFor`, unit and integration tests.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Visitor to `/cabinet/cards` | Untrusted query (`profile`, `sample`) reaches the server |
| Stored BGG text to JSON | Titles, designers, mechanics and locations from BGG are served to browsers |
| Site to third parties | The endpoint could be scraped as a BGG data relay |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |

| T-05-02-01 | Tampering | `CardsEndpoint.Handle` query | medium | mitigate | `profile` checked by `SectionDesigns.TryGet`, `sample` by `SampleCatalog.TryResolve`; no other parameter read; unknown sample falls back to the synced collection and is never echoed |
| T-05-02-02 | Denial of service | card JSON building | medium | mitigate | Built once per collection view and profile (`Lazy`), samples once per process from a fixed allowlist; a revalidation answers 304 without rebuilding |
| T-05-02-03 | Repudiation (terms) | card payload relaying BGG data | medium | mitigate | Field allowlist test; ranked rating, families, descriptions, image candidates and BGG URLs never serialised; no CORS headers; undocumented route |

| T-05-02-05 | Tampering (stored XSS) | BGG text in JSON | high | transfer | The JSON is data only; rendering via `textContent` is enforced in the card plans and by the repository lint (canon XSS: covered by `/gsd-secure-phase`) |
</threat_model>
