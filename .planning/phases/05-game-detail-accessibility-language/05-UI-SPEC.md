# Phase 5 — UI Design Contract

> Visual and interaction contract for the pull-out, the detail card (desktop dialog and phone sheet), the keyboard and screen-reader model, the English and Dutch site, and the polish register folded in from the previous phase's UI review. Generated by gsd-ui-researcher, verified by gsd-ui-checker.
>
> **Reading guide.** This phase **extends** the approved contracts in `04-UI-SPEC.md`, `03-UI-SPEC.md` and `02-UI-SPEC.md`. It re-decides nothing they lock: the wood palette and 60/30/10 split, the accent reserved list, the type scale (3 fixed page sizes, 2 weights), the spacing scale, the strict-CSP renderer rules, the furniture finish and shade cap, the box visuals, the status line, the footer credit. Where this file is silent, those files apply. Where this file contradicts one of them, **this file wins for this phase** and says so in "What this phase changes". Values tagged **FIXED** are not for tuning. Values tagged **STARTING VALUE** are first guesses for the review rounds (consolidated in "Tuning Register").
>
> **The owner's pick.** The card look is **direction B, the index card** (chosen 2026-10-09 from three mocked directions). Its open sub-choices stay as mocked: normal bold sentence-case headings (H2), a small colour chip in each expansion row in that expansion's own colour (X1), a plain dim of `rgb(20 10 4 / 0.62)` behind the card, never a blur (D1), and the "EN · NL" text toggle (T1). The mockup is `ui-refs/card-directions/card.html` with `?d=b`; the pictures are `b-desktop-en.png`, `phone-sheets-nl.png` (columns 3 and 4), `toggle-desktop-en.png` and `toggle-phone-nl.png`. The mockup's CSS is the **starting value** for this contract. Where this file differs from the mockup it says why.
>
> **Repository rule reminder for executors.** This file uses requirement keys and decision IDs because it lives in the planning folder. Nothing copied from it into code, markup, strings, tests, docs or comments may contain them. Copy strings in the Copywriting Contract are written so they can be pasted as-is. JavaScript comments are `/** ... */` doc blocks only; C# comments are `///` only.
>
> **Privacy.** This file and its reference images use invented titles, designers and locations only ("Lantern & Harbour", "Study, shelf 3" and similar). Nothing from the owner's collection appears here. Review screenshots from the real collection are sent as images and never committed.
>
> **Grounding.** Written against the running code: `wwwroot/css/cabinet.css`, `wwwroot/css/site.css`, `wwwroot/js/render.js`, `wwwroot/js/cabinet.js`, `wwwroot/js/copy.js`, `Pages/Index.cshtml`, `Pages/Shared/_Layout.cshtml`, `Pages/SyncStatusText.cs`, `GameDetails`. One name clash is avoided on purpose: the mockup calls its 28px line height `--rule`, but `.placement` already uses `--rule` for a colour, so this contract calls the card's line height **`--ruling`**.

## Spacing Scale

Unchanged scale for page chrome (multiples of 4: 4, 8, 16, 24, 32, 48, 64).

**Card geometry** uses the same scale for padding and gaps, plus one card-only unit:

| Token | Value | Usage on the card |
|-------|-------|-------------------|
| xs | 4px | Gap between an icon and its text; gap inside a row |
| sm | 8px | Photo border; close button offset from the corner; chip to text gap beside the 16px gap |
| md | 16px | Phone card padding inline; gap between header columns on phone |
| lg | 24px | Desktop card padding inline; gap between header columns on desktop |
| xl | 32px | Space reserved at the end of the scrolling content on phone, above the hole |
| `--ruling` | **28px** | The card's line height and vertical rhythm. See exceptions |

**Exceptions (all intentional):**

- **`--ruling: 28px`** is a multiple of 4 but not on the declared scale. It is the one card-only unit. Every ruled text line is exactly 28px tall and every vertical gap between ruled blocks inside `.card-ruled` is a whole multiple of it (**FIXED**). The rule does not reach the header, which is the unruled typed zone above the red rule and uses the normal 4px scale. **Two declared uses of the ruling outside `.card-ruled`:** the header's top padding and the phone sheet's grip strip are each one ruling (`var(--ruling)`, 28px), so the card opens with one blank line above the title, as a real index card does.
- **Tap targets (FIXED):** the close button is 44 by 44px. Language toggle items are 44px tall. Pressable rows inside the ruled area follow the rule in "Tap rows". Every control is at least 24px in both dimensions, and the preferred 44px is met on phones and coarse pointers.
- **Card width and height (STARTING VALUE):** desktop `min(640px, 100vw - 48px)` wide, `max-height: calc(100vh - 64px)` (use `100dvh` where supported); phone full width, `max-height: 90dvh` (fallback `90vh`). 640 is not on the scale; it is a measure, not a gap.
- **Cover columns:** header grid `208px 1fr` on desktop, `128px 1fr` on phone (cover cell includes the 8px photo border on each side).
- **Handle:** 40 by 4px (radius 2px), 8px from the top of the sheet; its drag zone is 28px tall (the grip strip).
- **Label column:** `9rem` on desktop, `7rem` on phone.
- **Safe area:** the sheet adds `env(safe-area-inset-bottom)` to its bottom padding.
- Page gutters, the header and the footer keep their phase-2 and phase-3 values. The language toggle adds one 44px row to the header (see "Language toggle").

In-cabinet geometry stays in millimetres scaled by `--u`.

## Typography

No new sizes and no new weights. Exactly **3 fixed page sizes (24, 16, 14)**, the in-cabinet fluid sizes (12 to 22px) and **2 weights (400, 600)**.

| Role | Size | Weight | Line height | Where |
|------|------|--------|-------------|-------|
| Card title | 24px | 600 | **28px** (`--ruling`; was 1.2 = 28.8px, a 0.8px change that puts wrapped titles on the rhythm) | `h2.card-title`, `dir="auto"`, `text-wrap: balance` |
| Year | 16px | 400 | 28px | under the title, colour `--paper-label` |
| Fact value | 16px | 600 | 28px | "2–4", "60–90 min", "Medium-light", "10+" |
| Fact label | 14px | 400 | 28px | "players", "play time", "weight 2.4 / 5", "min. age"; colour `--paper-label` |
| Section label | 14px | 600 | 28px | headings "Owned expansions", "Stored in" (the `h3` and `dt` with weight 600); colour `--paper-label`. Normal bold, sentence case, no small capitals, no letter spacing (H2) |
| Row label (`dt`) | 14px | 400 | 28px | "BGG rating", "Designers", "Mechanics"; colour `--paper-label` |
| Body value | 16px | 400 | 28px | location, rating, designers, expansion row titles, the base row |
| Mechanics | 14px | 400 | 28px | the quiet wrapped list, joined by a middle dot, `lang="en"` |
| Quiet note | 14px | 400 | 28px | "More details arrive after the next sync." colour `--paper-label` |
| BGG link | 16px | 400 | 28px | underlined, `text-underline-offset: 3px`, colour `--ink` |
| Language toggle | 14px | 600 current, 400 other | 44px box | see "Language toggle" |
| Skip link, games-list panel | 14px link, 16px entries | 400 | 44px rows | see "Skip link and games list" |
| In-cabinet text | unchanged except the two-step rule in "Polish register", which applies to **one-line** spine and upright titles (12 or 16px) and one-line flat, layer and orphan titles (12 or 14px) only. A **two-line** upright expansion keeps the earlier rule unchanged: title `clamp(12px, 0.25 x width, 14px)`, second line 12px | 600 / 400 | unchanged | 12px floor stays |

- Every ruled text line is `line-height: 28px` as a **length**, not a ratio. At 16px that is 1.75 and at 14px it is 2.0, both above the 1.5 that text-spacing overrides ask for.
- **Non-Latin titles and BGG names:** `dir="auto"` on every BGG text element, `unicode-bidi: plaintext`, `overflow-wrap: anywhere` on the title and expansion row titles, `hyphens: manual`. No `lang` attribute on titles, designers or locations (the language is unknown). Mechanics carry `lang="en"` (BGG's mechanic names are English).
- **Mixed-script drift guard (risk, tested):** a fallback font with taller metrics can make a fixed 28px line box a few pixels taller in some browsers, which would slide the ruling out of step for the rest of the card. The contract's answer is a browser test, not a hack: with the edge-case sample (Latin, Cyrillic, Japanese, Thai, Arabic and an emoji title, the same set in a designer name and an expansion title), every ruled block's height must be an exact multiple of 28px at 390px and 1440px. If one script drifts, the lever is `display: flow-root` on that block with its own ruling background origin, so drift cannot pass to the next block. Flagged in "Conflicts and open points".
- Weights stay exactly 400 and 600. Headings are not 700.

### Focus ring on paper (contract delta to reserved-list item 3)

| Surface | Ring |
|---------|------|
| Wood, wall, dimmed cabinet (boxes, toggle, sync controls, skip link, credit, games-list panel) | 2px solid `--wood-light` (accent), 2px offset. Unchanged |

## Pull-out choreography (D-01, D-02, D-06, D-08)

The moment the owner wants: the box comes off the shelf, a spine turns to show its cover, and the cover grows into the card. It must feel like taking a real box off a shelf, and the empty slot staying visible sells it.

### What animates (FIXED)

- **One element only:** the pulled-out box, as one named view-transition snapshot, `pull`. No other box is captured, transformed, dimmed or filtered. No 3D transform on any DOM element: the "turn" is a flip of two flat snapshots (the old one turns away, the new one turns in), run by keyframes on the transition's `::view-transition-old(pull)` and `::view-transition-new(pull)`.
- **Our own keyframes touch `transform`, `scale` and `opacity` only.** The browser's built-in group animation also interpolates the snapshot group's width and height; that is part of the browser's own snapshot machinery on one pseudo-element and is accepted (see "Conflicts and open points").
- **The dim and the card appear through the root cross-fade** (the new root state contains the dimmed backdrop and the paper). On phones the sheet is its own named group `card` so it can rise.
- **Backdrop: a plain dim, never `backdrop-filter`, never `filter: blur()`** (D-03). Blurring hundreds of boxes stutters on cheap phones.

### Kinds of pull

The kind is decided from the box's `data-kind` at the moment of the tap and written to `html[data-pull-kind]` for the length of the transition.

| Kind | Which boxes | Motion |
|------|-------------|--------|
| `turn-y` | `spine`, `expansionSpine` (upright, spine facing out) | Lifts, turns about the vertical axis (`rotateY`), widens into the cover |
| `turn-x` | `flatBox`, `expansionLayer`, `orphanExpansion` (lying, spine facing out) | Lifts, tips about the horizontal axis (`rotateX`), grows into the cover |
| `lift` | `cover` (already facing out, with art or generated) | Lifts and grows into the cover. **No turn** (D-01) |
| marker | `moreMarker` ("+N more") | The tap pulls out the **base game's own box** (the box in the same family with the same `data-family-id` whose `data-game-id` is the base), with that box's kind. The marker itself never moves |

### Tokens (D-02), declared on `:root` so the pseudo-elements inherit them

| Token | Value | Tag |
|-------|-------|-----|
| `--pull-open` | `350ms` | STARTING VALUE (D-02). Tap to readable card |
| `--pull-close` | `250ms` | STARTING VALUE (D-02, R1). A bit faster, it gets out of the way |
| `--pull-dur` | `var(--pull-open)`; `html[data-pull-dir="close"]` sets it to `var(--pull-close)` | FIXED mechanism |
| `--pull-ease-out` | `cubic-bezier(0.2, 0.7, 0.2, 1)` | STARTING VALUE |
| `--pull-ease-in` | `cubic-bezier(0.5, 0, 0.9, 0.4)` | STARTING VALUE |
| `--pull-flip-share` | `0.45` | STARTING VALUE. The share of the duration the old snapshot spends turning away; the new one turns in during the rest, so the two are edge-on (invisible) at the same moment |
| `--pull-perspective` | `900px` | STARTING VALUE |
| `--pull-lift` | `1.06` | STARTING VALUE. Peak scale of the lift (the box comes toward the viewer) |
| `--fallback-open` | `200ms` | STARTING VALUE. Plain fade-open, browsers without View Transitions |
| `--fallback-close` | `150ms` | STARTING VALUE |
| `--card-fade-reduced` | `150ms` | STARTING VALUE (D-08) |
| `--swap-fade` | `120ms` | STARTING VALUE. Cross-fade when swapping between a base game and an expansion |

### Timeline

| Time (open, 350ms) | What happens |
|--------------------|--------------|
| 0 | The tap. The source box is already captured as the old snapshot, at its (hover-lifted) position. The slot behind it shows the empty cubby (the box is excluded from the root snapshot and hidden in the new state). The dim starts to fade in with the root cross-fade |
| 0 to 158ms (45%) | Old snapshot turns away (`rotateY` 0 to -90deg for `turn-y`, `rotateX` 0 to 90deg for `turn-x`), ease-in. Skipped for `lift` |
| 0 to 140ms | Lift: the image pair scales 1 to `--pull-lift`, then settles back to 1 by the end |
| 0 to 350ms | The group moves and resizes from the box's rectangle to the card cover's rectangle, ease-out |
| 158 to 350ms | New snapshot (the cover) turns in (`rotateY` 90deg to 0 or `rotateX` -90deg to 0), ease-out |
| 350ms | The cover rests in the photo frame; the paper and its text are fully faded in |

Close (250ms) is the same choreography reversed in meaning, not run backwards: the old snapshot is the cover and the new one is the box, so the cover turns away first and the box turns in. It uses the same share and the same easings.

Phone: `.card` is named `card` for the length of the transition (`@media (max-width: 40rem)`). Its new-only snapshot rises with `card-rise` (translate 32px to 0 plus opacity 0 to 1 over `--pull-dur`, ease-out). On close its old-only snapshot sinks with `card-sink` (translate 0 to 32px plus opacity 1 to 0, ease-in). A sheet that was dragged down closes from where the finger left it, because `translate` is part of the captured snapshot.

### The sequence in script (open)

1. **Prepare, nothing visible yet.** Build the card content from the card record into the closed dialog. Set `--cover-ratio` on `.card-cover` with `setProperty`. Start loading the cover image on `pointerdown` or on `keydown` of Enter or Space, not on hover (reduced data, the phase-4 rule stands).
2. **Wait for the cover, briefly.** `await Promise.race([image.decode().catch(...), timeout(200ms)])` (STARTING VALUE 200ms). If it is not ready, go on: the frame shows its edge-colour fill and the picture appears when it arrives. No spinner, no skeleton. A generated cover needs no wait.
3. **Choose the path** (see "When there is no pull-out").
4. **Old state:** set `data-pulling="source"` on the box.
5. `document.startViewTransition(() => { ... })`. Inside the callback, in this order: remove `data-pulling` from the box; set `data-out` on the box; set `data-pulling="target"` on `.card-cover`; `dialog.showModal()`; push the history step (see "Back button"); focus the title (`focus({ preventScroll: true })`).
6. **When `transition.finished` settles:** remove `data-pulling` from the cover and `data-pull-kind` and `data-pull-dir` from `<html>`. If the transition was skipped, the callback still ran, so the state is already correct.
7. **Ignore taps on boxes while a transition runs** (about 350ms). A second tap during that window does nothing.

Close mirrors it: set `data-pull-dir="close"`; old state `data-pulling="target"` on the cover; in the callback remove it, `dialog.close()`, drop `data-out` from the box and set `data-pulling="source"` on the box; after `finished` remove names and restore focus.

### The empty slot stays visible (I-A)

While the card is open the source box has `data-out`, which is `visibility: hidden`. The cubby behind it, its back planks, shade and the neighbouring boxes are unchanged and visible behind the dim, so the box reads as having come out of the shelf. On close the box returns into the same slot. `data-out` uses `visibility`, never `opacity` or `display`, so a later dimming state (`opacity`) on the same element does not conflict and the slot never collapses.

### The cover spot takes the box's real proportions (I-B)

- The card record carries `ratio`, the box front's width divided by height from the box-size chain (real size, flat cover shape or estimate). `.card-art` is `aspect-ratio: var(--cover-ratio)`, clamped to **0.6 to 2.0** (STARTING VALUE) so an extreme box does not make a card taller than the screen. Inside, the art is fitted whole with `object-fit: contain` on the four edge-colour fill bars, exactly as on the cabinet, so the morph from a face-out cover is pixel-identical in shape and a spine's cover grows into the same fitted look.
- **No usable art:** the cover spot is the generated cover (palette or art colour, pattern, title plate) at that ratio, with the plate's text `aria-hidden` because the title is the next element. The morph from a generated cover is the same `lift`.
- **Variants:** the card cover uses the 480px file on desktop and the 240px file on phone (at least 1.9 times its CSS width). The card data carries the URL for the requesting profile.
- **Never cropped, stretched, rotated, recoloured, blurred or overlaid.** The corner mounts are painted by the frame's background and sit under the art, so they appear on the white border only.

### When there is no pull-out (plain fade, same card)

| Case | Behaviour |
|------|-----------|
| Browser without View Transitions (`document.startViewTransition` missing) | Plain fade-open: the dialog opens with a `--fallback-open` opacity fade (dim and card together); close is a `--fallback-close` fade-out, then `close()`. The box gets `data-out` at once and loses it at the end of the close. **No second hand-built morph** (D-01) |
| Reduced motion (`prefers-reduced-motion: reduce`, read at every tap) | No lift, turn, slide, morph or drag spring. The **View Transition is not started at all**. The dialog opens with an opacity fade of `--card-fade-reduced` (150ms) for the card and the dim together. **The box stays in place** (no `data-out`) with a clear highlight: `outline: 2px solid var(--wall-text); outline-offset: 2px; z-index: 2` via `[data-open]`. The highlight is `--wall-text`, not accent. It is removed on close. Close is the same 150ms fade |
| The box is not on screen (fewer than half its area inside the viewport; for example the card was opened from the games list while the page was scrolled elsewhere) | Plain fade, as for a browser without View Transitions. The page is never scrolled to reveal the box |
| The card was swapped to another game before closing | Plain fade-out for the card and dim; the source box reappears in its slot with the same fade (no flight, because the cover on screen is no longer the box's own cover). See "Swapping" |
| The card data has not arrived or failed | The card opens with the pull-out as normal and shows what the placement knows (cover, title, BGG link) plus the quiet note. See "Missing details" |
| The viewport crosses the phone breakpoint while a card is open | The card closes at once with a plain fade, then the cabinet reloads for the new profile. No reverse flight |

### Sync waits for the card (D-06)

- While a card is open, `onCollectionChanged` only records that the collection changed. It does not fetch, redraw or replace anything. The card is left alone, including its data.
- When the close transition has **finished** (the box is back in its slot), the stored change triggers the existing quiet redraw. Then the cards data is refetched for the new version. So the reverse flight always has its box, and nothing jumps under the reader's eyes.
- A second change while the card is open collapses into the same single pending redraw.
- Keyboard focus after the redraw follows the existing rule (box with the same `data-entry-id`).

### Performance (FIXED)

One named snapshot at a time. No `will-change` except on `.card` **while a sheet drag is in progress**, applied by a stylesheet rule on `.card[data-moving]` (script only toggles the attribute, never writes a style) and removed on release. No `filter`, no `backdrop-filter`. No animation of anything but `transform`, `scale` and `opacity` in our own keyframes. The dialog is created once and reused. The card's shadows (two, plus the inset edge) and its single ruling background sit on `.card` only.

- **Drag zone:** the grip strip and the header only (pointer events, `touch-action: none` on those two). ## Back button (D-05, R7)

**Goal:** Back always does exactly one sensible thing: it closes the card. Closing any other way leaves no dead history step. The address never changes.

**What the browsers do (researched):** a modal `<dialog>` is a close-request target. In Chromium, Android's Back (button or gesture) fires a close request: the dialog's `cancel` and `close` events run and **history is not traversed**. This depends on user activation since the dialog opened, and Chromium skips the close request without it. Firefox and Safari have no such integration and Back traverses history normally. Because both behaviours exist, the mechanism must work in both without browser sniffing.

**The mechanism (belt and braces):**

1. **Open:** after `showModal()`, call `history.pushState({ card: true }, '')` with **no URL argument** (the address does not change) and set `historyStep = true`.
2. **A close from history (`popstate`):** the step is already gone. Set `historyStep = false`, then close the dialog through the normal close routine. The `close` handler sees `historyStep === false` and does nothing more.
3. **A close from anywhere else** (✕, Escape, outside tap, drag, Chromium's close request, the profile change): the dialog's `close` event handler sees `historyStep === true`, sets `ignoreNextPop = true`, sets `historyStep = false` and calls `history.back()` to remove the step. The `popstate` that follows is swallowed because `ignoreNextPop` is set (then cleared).
4. **Swapping between a base game and an expansion does not push a step.** One card, one step (D-05: Back closes the whole card even after a swap).
5. **A reload or a bfcache restore with a stale `{ card: true }` state:** on load, if `history.state?.card` is set, `history.replaceState(null, '')`.
6. **Re-open race:** if a card is opened while a `history.back()` from the previous close has not delivered its `popstate` yet, wait for that `popstate` (at most 150ms) before pushing, so the stack never holds two steps.
7. The Navigation API is not used (Chromium only).

**Must be verified in the review build on a real device each:** Chrome on Android (button and gesture, with and without a prior tap), Safari on iOS (swipe from the edge), Firefox on Android, desktop Chrome, Firefox and Safari Back. The acceptance is the same everywhere: one Back closes the card, and a second Back leaves the site as it would have before.

## Card anatomy (D-11 to D-16)

**Visual hierarchy.** One focal element: **the cover**, the box the visitor just pulled out, and the first read. The title is the second read. The game-night strip is the third: its icons and bold 16px values on the first ruled lines answer "can we play this tonight?" before anything else. Everything below it is quieter (14px labels in `--paper-label`, values in weight 400).

### Order (FIXED)

1. **Header:** cover, title, year. Closed by the red double rule.
2. **The ruled area**, in this order, each group separated from the next by **one blank ruled line**:
   1. (expansion cards only) the "Expansion for" row or rows
   2. the game-night strip, or, when no detail is known at all, the quiet note
   3. Stored in (only when the game has a location)
   4. Owned expansions (only when the game has some)
   5. BGG rating, designers, mechanics
   6. the BoardGameGeek link, last
   7. the punched hole

Nothing is reordered per language or per viewport. DOM order equals reading order.

### The ruling, and how every line stays on it (weak point 2)

One background on `.card-ruled`, not on each block, so all rules are continuous:

```css
.card-ruled {
  background-image: repeating-linear-gradient(
    to bottom,
    transparent 0 calc(var(--ruling) - 1px),
    var(--paper-rule) calc(var(--ruling) - 1px) var(--ruling)
  );
  background-position: 0 calc(-1 * var(--ruling-drop));
  line-height: var(--ruling);
  padding: var(--ruling) 24px 0;
}
```

- **Where the line sits (STARTING VALUE):** with a 28px line box and `--ruling-drop: 4px`, the rule is at 23px to 24px inside each line box. The baseline of 16px system text is about 20px, so the rule sits about 3px under the baseline and descenders cross it, as on a handwritten card. Tune `--ruling-drop` in a crop at 14px and 16px, and only to 4px or 8px (the mockup used 6px, which is off the 4px grid).
- **The five rules that keep wrapped text on the rhythm (FIXED):**
  1. Every text element in `.card-ruled` has `line-height: var(--ruling)` as a **length**, so k wrapped lines are exactly k times 28px.
  2. No vertical padding or margin is anything but a whole multiple of `--ruling`, written as `calc(n * var(--ruling))` with integer `n`. No half lines.
  3. Nothing inside has a fixed height that is not a multiple of `--ruling`. Icons and chips are absolutely positioned inside their line, so they never change a line box.
  4. A two-column row (label and value) grows by whole lines: the label stays on the first line and the value wraps beside it, so "Mechanismen", a long designer list or a three-line expansion title all end on a rule.
  5. Long unbroken words (German compounds, Thai, URLs in titles) use `overflow-wrap: anywhere` so they wrap instead of widening a row.
- Horizontal padding is 24px (desktop) and 16px (phone); the ruling runs edge to edge.
- Tested as in "Typography" (every ruled block a multiple of 28px).

### The header and the red rule (weak point 2, continued)

The header is **not ruled**: it is the typed title zone above the red rule, exactly as on a catalogue card. Its job is that wrapped titles end tidily above the rule.

- Title and year are `28px` lines. The title block is `align-self: end`, the cover cell `align-self: start`, so a short title sits on the cover's bottom edge and a long one fills the row.
- **The title never truncates.** It wraps onto 2, 3 or more lines (`overflow-wrap: anywhere`, `text-wrap: balance`) and the header grows. The year is always the last line.
- **The header's row is as tall as the cover frame rounded up to a whole ruling:** `--cover-frame-h: calc(var(--cover-w) / var(--cover-ratio) + 16px)` (`--cover-w` is 192px on desktop and 112px on phone, `--cover-ratio` is set from data), and `grid-template-rows: minmax(round(up, var(--cover-frame-h), var(--ruling)), auto)` inside `@supports (min-height: round(up, 10px, 28px))`. Without `round()` the row is simply as tall as its content, which is at most one ruling off.
- **Bottom padding is 16px (the normal 4px scale), then the `3px double var(--paper-red)` border.** So the year always sits the same distance above the red rule, whether the title took one line or four. The ruled area starts directly under the red rule, and its first line is a blank ruled line (the padding-top), so the ruling and the typed zone never fight.
- Desktop header padding: `var(--ruling)` top, 24px inline, 16px bottom. Phone: `var(--ruling)` top (the sheet's grip strip), 16px inline, 16px bottom.
- **Scope of the rhythm rule:** "whole multiples of `--ruling`" applies to everything **inside `.card-ruled` only**. The header is the unruled typed zone above the red rule. Its top padding is one ruling (a declared Spacing exception); everything else in it uses the normal 4px scale, and its 28px title lines match the ruling visually.

### The game-night strip (D-11, D-16)

- `<ul class="facts">`, four possible entries in this fixed order: **players, play time, weight, minimum age.** An entry whose value is missing is left out and the others close up; no placeholder, no dash, no "unknown".
- **Desktop:** two columns (`grid-template-columns: repeat(2, 1fr); column-gap: 24px`). **Phone:** one entry per line (the mockup's choice, and it keeps every entry one clean ruled line).
- **Anatomy of one entry, as inline flow, not flex:** `li.fact { position: relative; padding-inline-start: 32px }` holding the icon (24px, absolutely positioned at the line's start, `top: 0`, so its bottom sits on the rule, which is 4px above the line box's bottom edge) and then `<span class="v">` (16px, 600) and `<span class="l">` (14px, 400, `--paper-label`) as inline text. Inline flow means a long label such as "zwaarte 2,4 / 5" wraps by whole lines instead of overflowing, and the entry grows from 28px to 56px with its neighbour in the grid row staying 28px.
- Icons are decorative (`aria-hidden="true"`, `focusable="false"`); the value and label are text, so every fact has a text label for screen readers (D-11).
- Icon stroke is `currentColor` (`--ink`), stroke width 1.75. Never the art colour.

| Fact | Known when | Value | Label | Notes |
|------|-----------|-------|-------|-------|
| Players | min or max is a whole number above 0 | `2–4` (en dash) when both are known and differ; one number when equal or only one is known | `players`; `player` when the value is exactly 1 | BGG's 0 counts as missing |
| Play time | min, max or the stated time is above 0 | `60–90 min` when min and max are both known and differ; otherwise the stated time, then min, then max, as `60 min` | `play time` | never "0 min" |
| Weight | weight is above 0 | the weight word in sentence case, for example `Medium-light` | `weight 2.4 / 5` (one decimal, language number format) | the word is the site's own label and is translated |
| Minimum age | age is above 0 | `10+` | `min. age` | |

**Weight words.** BGG publishes five named levels (light, medium-light, medium, medium-heavy, heavy) but no numeric cut-offs, so the bands are the **midpoints between the levels (STARTING VALUE):** below 1.5 light; 1.5 up to 2.5 medium-light; 2.5 up to 3.5 medium; 3.5 up to 4.5 medium-heavy; 4.5 and above heavy. The mockup's 2.4 reads "Medium-light". The owner can move the cut-offs; they live in one pure function covered by `node --test`.

### The quiet note (D-16)

When none of players, play time, weight, minimum age, rating, designers or mechanics is known (a new game not enriched yet, or a failed enrichment), the strip is replaced by one quiet line in the first ruled slot: Quiet note style, `--paper-label`, wrapping on the ruling. Copy in the Copywriting Contract. The rest of the card (location, expansions) still shows if it has data, and the cover, title, year and BGG link always show. No icon, no warning colour, no weight change. If the card data failed to load at all, the card shows exactly this.

`<dl class="card-where"><dt>Stored in</dt><dd>{location}</dd></dl>`, a label column (`9rem` desktop, `7rem` phone, `dt` 14px 600 `--paper-label`) and the value (16px 400) wrapping beside it. **The whole group is absent when the game has no location.** No card ever says "unknown". ### Tap rows (weak point 1)

The mockup's rows and link were 28px tall: above the **FIXED 24px floor** but below the comfortable 44px for a thumb. The rule, **FIXED**:

> **Every pressable row inside the ruled area is `--hit-rows` rulings tall, where `--hit-rows` is 1 on a fine pointer and a wide screen and 2 on a coarse pointer or a phone-width screen.**

```css
:root { --hit-rows: 1; }
@media (any-pointer: coarse), (max-width: 40rem) { :root { --hit-rows: 2; } }
.exp-row, .card-link { min-height: calc(var(--hit-rows) * var(--ruling)); }
```

- With `--hit-rows: 2` a row is **56px**, above the 44px preferred size. The text sits on the **first** ruled line; the second line is the blank line that separates entries, and it belongs to the row's hit area. A title that wraps onto two lines fills the 56px with no wasted space.
- **Hit areas tile and never overlap:** rows are contiguous blocks, so a tap always lands on exactly one row. No pseudo-element extends a hit area over a neighbour.
- Always whole multiples of `--ruling`, so the rhythm never breaks. A row whose title wraps to 3 lines is 3 rulings (84px).
- With a fine pointer the row is 28px (above 24px), with a hover tint (`@media (hover: hover)`: `background: rgb(42 26 16 / 0.06)`) and no motion. On touch an `:active` tint of the same colour, `-webkit-tap-highlight-color: transparent`.
- **Cost, stated:** a phone card with three expansions is 84px taller than the mockup's. The sheet scrolls (S1), so this is accepted. Lever if the owner finds long expansion lists too tall in review: show one-line rows at 44px with the ruling suspended inside that list only (breaks cue 2 for that block; not recommended).
- The close button (44px), the language toggle items (44px), the sync controls (44px) and the credit link (44px) already meet 44px.

## Keyboard and screen reader (D-17 to D-20)

### One tab stop, spatial arrows (D-17)

- The cabinet mount `#cabinet` gets `role="group"`, `aria-label` ("Cabinet" / "Kast") and `aria-describedby` pointing at a visually hidden hint (copy below). Boxes stay native `<button>`s with their existing names.
- **Roving tabindex.** Exactly one `.placement` has `tabindex="0"`; every other has `tabindex="-1"`. The one with `0` is the box that last had focus (tracked by `data-entry-id`), or **the first box in DOM order** on the first visit. Any focus on a box (keyboard, click or tap) makes it the one. After a redraw the same entry id keeps it; if that box is gone the first box takes it. Tab enters the cabinet on that box; the next Tab leaves the cabinet.
- **Keys** (handled on `keydown` in the cabinet; the handled key calls `preventDefault()` so the page does not scroll):

| Key | Moves to |
|-----|----------|
| ← and → | the neighbouring box **on the same shelf**: the nearest box to the left or right that does not overlap the current box horizontally. A pile or stack counts as one position, entered at the box whose vertical centre is nearest the current one. At the end of a shelf the key does nothing (no wrap) |
| ↑ and ↓ | the nearest box above or below **by on-screen position**, which walks up and down through a flat pile or expansion stack one box at a time, then on to the shelf above or below, including across a section boundary |
| Home, End | the first and last box in DOM order (reading order) |
| Enter, Space | opens the card (a native button click) |

- **The spatial rule (STARTING VALUE, pure function, unit-tested):** for ↑ and ↓, candidates are boxes entirely above (or below) the current box's top (or bottom) edge, within 2px of tolerance. The score is `gap along the axis + 2 x gap across the axis`, where the across gap is 0 when the two boxes overlap on that axis; the lowest score wins, ties go to the box earlier in DOM order. For ← and →, candidates are limited to boxes with the same `data-shelf`, the across axis is vertical, and the same score applies. The geometry comes from `getBoundingClientRect()` at the time of the key press, so it is correct on both profiles and in expansion stacks.
- **`data-shelf`** (new, set by the renderer) is `"{sectionIndex}:{shelfOrdinal}"`, the same shelf ordinal the renderer already computes for `data-board`.
- The cabinet's geometry is physical, so ← always means visually left, whatever the language.
- Focus moves with `focus()`; the browser scrolls the box into view and `scroll-margin: 16px` on `.placement` keeps it off the screen edge. The focus ring is the existing accent ring, painted above the shade (z-index 2).
- Dimmed boxes (the filters phase) stay in the roving set and stay tappable; nothing here assumes every box is bright.

### Skip link (D-18)

- `<a class="skip-link" href="#games-list-start">` is the **first focusable element of the page**, before the header. Copy in the Copywriting Contract.
- Hidden until it takes focus: a visually hidden rule when `:not(:focus)`. When focused: `position: fixed; inset-block-start: 8px; inset-inline-start: 8px`, `z-index: 10` (page level, outside the cabinet's two layers), `min-height: 44px`, padding `8px 16px`, 14px 400, `color: var(--wall-text)`, **solid `--wood-dark` background** (so it covers the title), 1px solid `--chrome-line` border, radius 4px, and the global accent focus ring (it sits on wood, so the accent ring is correct). The look matches the sync button.
- Activating it (a script handler) focuses the first list entry; without script the fragment link targets that entry's id, which moves the sequential focus point there.

### The games list for screen readers and keyboard users (D-18 to D-20)

```
<section class="games-list" aria-labelledby="games-list-title">
  <h2 id="games-list-title">All games</h2>
  <ul>
    <li><button id="games-list-start" tabindex="-1" aria-haspopup="dialog">Title (2019), 2–4 players, ...</button>
      <ul> <li><button tabindex="-1" aria-haspopup="dialog">Expansion title (2021), expansion for Title, ...</button></li> </ul>
    </li>
  </ul>
</section>
```

- **Position in the page:** in `main`, before the cabinet group, so a screen-reader user meets it first. It is built from the card data after it arrives (the cabinet itself needs script anyway). **Until the card data arrives, or if it fails, the list shows every game by title only** (from the cabinet's own layout data, with "expansion" marked where known) and no facts; the entries gain their facts when the card data arrives. With no games the list holds only its heading, and the skip link lands on the heading. (Owner confirmed, 2026-10-09.)
- **Visually hidden, not removed:** `.games-list:not(:focus-within)` uses the clip-rect hiding pattern (1px box, `clip-path: inset(50%)`, `overflow: hidden`, `white-space: nowrap`, absolutely positioned). It is never `display: none` or `aria-hidden`.
- **Order (D-19):** base games A to Z by BGG title using `Intl.Collator(pageLanguage, { numeric: true, sensitivity: 'base' })` (so "Game 2" sorts before "Game 10", and accents do not split a letter). Each owned expansion is a nested list item under its base game. An expansion that expands several owned bases is nested under each of them. An **orphan expansion** (no owned base) sorts at the top level under its own title, and its name says it is an expansion for its base game.
- **Each entry announces the game-night facts (D-20)** and nothing else: `{title} ({year}), {players}, {play time}, {weight word}`. A missing fact is left out together with its comma, and a missing year drops the parentheses. An expansion adds `expansion for {base}` after the year. Age, rating and location are left to the card. Examples in the Copywriting Contract, English and Dutch. A listener hears down the list and opens a card only for the full details.
- **Roving, not a tab trap:** every entry is `tabindex="-1"`. Entering the list is by the skip link (or the screen reader's own virtual cursor); inside it ↑ and ↓ move between entries (document order, including nested ones), Home and End jump to the first and last, Enter and Space open the card. **Tab leaves the list** to the next tabbable element in DOM order (the cabinet's active box), so ordinary tabbing never lands on 300 invisible buttons and never flashes the panel.
- **A visible panel while focus is inside the list (needed for focus visibility):** `.games-list:focus-within` becomes a fixed panel so a sighted keyboard user who used the skip link can see where focus is: `position: fixed; inset: 16px auto 16px 16px; width: min(24rem, 100vw - 32px); overflow-y: auto; z-index: 10; background: var(--wood-dark); border: 1px solid var(--chrome-line); border-radius: 4px; padding: 8px`. Entries are 44px rows, 16px `--wall-text`, nested lists indented by 16px, with the accent focus ring. The heading shows too. It disappears when focus leaves it, and while a card is open (the page behind is inert). This is the one visible trace of the list; it is not a list view for every visitor (still deferred). See "Conflicts and open points".
- **Opening from the list** opens the same card. The pull-out flies from that game's cabinet box if at least half of it is on screen, otherwise a plain fade is used (never scrolls the page). **On close, focus returns to that list entry**, not to a cabinet box.

### What is announced, and the single live region

- The page keeps **exactly one live region, `#sync-note`**, with the phase-3 rules unchanged (only the visitor's own press writes to it; nothing that ticks is announced). **This phase adds no live region.**
- **Card open:** the native modal dialog is named by `aria-labelledby` (the title) and focus goes to the title, so a screen reader announces the dialog and then the title. A separate "card opened" message would double-announce, so there is none.
- **Card close:** focus returns to the box (or list entry), whose name is read. No message.
- **Swap:** focus moves to the new title and `aria-labelledby` renames the dialog; the new game's name is read. No message.
- **"+N more":** the dialog name is announced as for any card, then the "Owned expansions" heading.
- **Language switch:** a full page load in the new language, so the new `<html lang>` and the new title are read by the browser as usual.

### Landmarks and the rest

`header` (title, language `<nav aria-label>`, sync block), `main` (games list section, the cabinet group), `footer`. The dialog is its own modal region. The decorative furniture elements stay `aria-hidden`. The sticky grip strip, the handle, the hole and every icon are `aria-hidden`.

### Which language is shown (D-22)

1. The functional cookie, if present and valid (`en` or `nl`).
2. Otherwise the first language in `Accept-Language` that is `nl` (including `nl-BE` and the like) or `en`; the quality order decides.
3. Otherwise English.

- **Cookie:** one functional preference cookie, name `lang` (STARTING VALUE: a short plain name), value `en` or `nl`, `Path=/`, `Max-Age` one year, `SameSite=Lax`, `Secure` in production, `HttpOnly` (script never reads it). No tracking, no consent banner, no other cookie.
- **Rendered from the first byte:** the server writes the page in the chosen language, so there is never a flash of the other. `<html lang="{code}">` follows (the layout currently hard-codes `en`). The response sets `Content-Language` and `Vary: Cookie, Accept-Language`; the page is not shared-cacheable. The layout JSON and the card data carry no language-dependent text, so their ETags do not change with the language.
- The scripts read `document.documentElement.lang` and pick their table, with no extra request.

### What is translated and what is not (D-24)

- **Translated (the site's own words):** every label, status line, note, button, heading, accessible name, weight word, relative time, the empty and error states, the footer version text, the page title, and the card's labels.
- **Never translated:** game titles, expansion titles, designer names, mechanic names and locations. BGG's terms forbid modifying its data, and Dutch players use the English mechanic names. Mechanics are marked `lang="en"`; titles get no `lang`.
- **Not translated on purpose:** the developer-only sample switcher and its strings (local development only).
- **Voice:** informal "je" (`Je kunt over 3 minuten opnieuw synchroniseren.`). Plain words, short sentences, no jargon, no exclamation marks, sentence case. "Cabinet" is `kast`, "collection" is `collectie`, "sync" is `synchroniseren`. The Dutch is a draft: the owner reviews a side-by-side table.

## Data the card needs (D-09, R6; names are proposals for the planner)

**Delivery:** a sibling endpoint, `GET /cabinet/cards?profile={phone|desktop}`, keyed by the collection version and the profile, **under the same ETag rules as the layout endpoint**: validated with `If-None-Match`, `Cache-Control: no-cache`, no cross-origin headers, undocumented, compressed. It is requested right after the cabinet draws (low priority), so first paint is not delayed, and again after every redraw. The response carries `version`; a response whose version differs from the layout on screen is discarded and fetched once more. The layout JSON itself is unchanged apart from the two attributes in "Assumptions". The card and the games list read from this data only, so the card is never empty and never shows a spinner halfway through the pull-out. (Riding inside the layout JSON is the alternative the planner may choose; the contract only needs the data present at the tap.)

**Only fields the card or the list shows are sent. Never raw BGG dumps (the relaying rule).** One record per collection entry:

| Field | Meaning |
|-------|---------|
| `entryId`, `gameId` | the entry (unique per copy) and the BGG id |
| `title`, `year` | BGG text and the year, or null |
| `isExpansion` | true for an expansion |
| `ratio` | box front width divided by height from the box-size chain (real size, flat cover shape or estimate) |
| `cover` | `{ url, width, height, fit, edges: { top, right, bottom, left } }` for the requesting profile's variant, or null for no usable art. Validated on read like the cabinet's art |
| `colour`, `toneIndex`, `patternIndex` | the stored spine colour pair (or null) and the palette and pattern indices, for the generated cover and the chip |
| `location` | the entry's storage location, or null (null on every game until locations are assigned) |
| `minPlayers`, `maxPlayers`, `playTime`, `minPlayTime`, `maxPlayTime`, `minAge`, `weight`, `rating` | the card's numbers; null when unknown; `rating` is BGG's average, one decimal. Zero means unknown. The ranked rating is **not** sent |
| `designers`, `mechanics` | string lists in BGG's order, already capped by the domain |
| `expansions` | on a base game: its owned expansions as `{ entryId, title, chip }`, `chip` being the expansion's spine colour as `#rrggbb` (art colour, else the palette tone's hex), validated on read |
| `bases` | on an expansion: its owned base games as `{ entryId, gameId, title, chip }`, and for a base that is not owned `{ entryId: null, gameId, title, chip: null }`; empty when unknown |

Not sent: the ranked rating, families, enrichment timestamps and versions, size estimates, image candidates, descriptions, and BGG URLs (the link is built from `gameId`). Size: about 0.6 KB per entry, so about 40 KB for 65 games and 240 KB for 400 before compression.

## Interaction, Motion and Accessibility Baseline (additions)

- **Motion:** the pull-out (350ms open, 250ms close, tunable), the 120ms swap cross-fade, the 200ms sheet spring-back and the existing 120ms hover lift. Everything respects `prefers-reduced-motion: reduce`: no lift, turn, slide, morph or spring; a 150ms opacity fade; the View Transition is not started. Include a belt-and-braces `@media (prefers-reduced-motion: reduce) { ::view-transition-group(*), ::view-transition-old(*), ::view-transition-new(*) { animation: none !important } }`.
- **Cursor:** `.placement { cursor: pointer }` (this amends the phase-2 `cursor: default`, which existed only because click did nothing).
- **Keyboard:** the cabinet is one tab stop; the games list is entered by the skip link and left by Tab; inside the card Tab is trapped by the modal dialog and Escape closes it. The tab order of the page is: skip link, language toggle, relative-time button, "Sync now", the cabinet's active box, the BGG credit.
- **Focus:** accent ring on wood and wall, `--ink` ring on paper, never `outline: none` on a control, never clipped. The title takes programmatic focus without a ring because it is not operable.
- **Touch:** every control 44px or the phone-and-coarse-pointer 56px rows; the close button 44px; no hit area overlaps another. Drag only from the grip and header.
- **Contrast (FIXED):** all text on paper at least 4.5:1 (`--ink` 15.8, `--paper-label` 7.5); toggle and skip link at least 4.5:1; every focus ring at least 3:1 on its surface; the handle at least 3:1 (3.59:1).
- **Zoom and reflow:** at 400% zoom the viewport is about 320 CSS px wide, so the phone sheet applies; no horizontal scroll on the card at any width from 320px. Fixed 28px line heights are at least 1.75 times the text size.
- **Forced colours:** `@media (forced-colors: active)` gives `.card` a `1px solid CanvasText` border and keeps icons on `currentColor`; the ruling and mounts may vanish, which is acceptable because every item is also text.
- **BGG text:** `textContent` only, everywhere on the card and the list; `dir="auto"` on every BGG string.
- **Strict CSP (FIXED):** no violation with a card open, no inline style, no inline script. Integration test still fails on `style=` attributes and inline script bodies.
- **Colour is never the only carrier of meaning:** an expansion's nature is in its words; the current language is bold and underlined as well as lighter.

## Conflicts and open points

Where the decisions, the mockup and the code pull against each other. The contract states what it assumes; the owner or the planner may overrule.

**Owner review, 2026-10-09:** the owner accepted every open point as proposed in `05-UI-CONSIDERATIONS-REVIEW.md` (O1 to O14), so each "Assumed" below is confirmed. Two follow-ups stay: the Back button must be checked on the owner's own phone in the review build (one Back closes the card, a second Back leaves the site), and the punched hole is dropped if review crops still read it as a dot.

1. **Focus ring on the paper is `--ink`, not accent.** The reserved list says the ring is accent everywhere. Accent on paper is 1.76:1, so the ring would be invisible. The list is otherwise unchanged. **Assumed:** ink on paper, accent everywhere else.
2. **Phone rows are 56px, not 28px.** The mockup's 28px rows are below 44px. Two-ruling rows fix that without touching the look, at the cost of an expansion list about 28px taller per entry on a phone. **Lever:** none recommended (see "Tap rows").
3. **Title line height 28px, not 1.2.** 24px at 28px is 1.17, a 0.8px change from the baseline rule, taken so wrapped titles stay on the ruling. The `--ruling` unit (28px) is not on the declared spacing scale. Both are card-only and documented.
4. **Mixed-script lines may drift.** A fallback font with taller metrics can grow a 28px line by a few pixels in some browsers. A browser test over Latin, Cyrillic, Japanese, Thai, Arabic and emoji will show whether any browser drifts. **Lever:** a per-block ruling origin for the offending block so drift cannot accumulate.
5. **"+N more" focuses the "Owned expansions" heading, not the title.** The title would scroll the card back to the top. A small deviation from "focus goes to the card's title".
6. **A visible panel while focus is inside the games list.** The list is visually hidden, but a sighted keyboard user who uses the skip link would otherwise focus invisible buttons, which fails focus visibility. The panel shows only while focus is inside it. **Lever:** accept invisible focus (not recommended).
7. **A swapped card closes with a plain fade, not a flight.** After a swap the cover on screen is not the source box's cover; flying it into that box would mislead. The box still returns to its slot.
8. **No pull-out for an off-screen box.** Opening from the games list with the page scrolled elsewhere uses the plain fade and never scrolls the page.
9. **The browser's own group animation interpolates width and height** of the one snapshot pair. Our keyframes touch `transform`, `scale` and `opacity` only. Accepted: it is a single pseudo-element on one box.
10. **Weight word cut-offs are midpoints.** BGG publishes five level names and no numeric bands, so the bands are 1.5, 2.5, 3.5 and 4.5. The owner can move them.
11. **Back behaviour differs by browser** and depends on user activation in Chromium. The mechanism handles both; it must be checked on real devices in the review build.
12. **The Dutch site name `Spellenkast` is a draft.** The title and `<h1>` are the site's own words, so D-24 says translate; the owner decides.
13. **Thin-box labels are hidden, not raised.** This changes engine data (empty labels), so the layout version is bumped and the golden files are re-recorded. Raising floors was rejected because it re-packs the whole cabinet for a few labels.
14. **Broken art stays invisible to visitors** (the phase-4 silent fallback is FIXED). The distinction is a DOM marker and a server-side count, not a visible one.
15. **The hole may be dropped** if the review crops still read it as a dot. It is decoration only.
16. **Header height is rounded up to a whole ruling only where `round()` is supported** (all current evergreen browsers); elsewhere the header is at most one ruling off, which is invisible.
17. **A language switch reloads the page.** It keeps the scroll position where browsers allow it, and the cabinet's data is served from the ETag cache.
