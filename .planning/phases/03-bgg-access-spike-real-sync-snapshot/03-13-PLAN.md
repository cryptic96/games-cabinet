## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 3`): "The owner's real BGG owned collection appears automatically in the deployed cabinet, kept fresh by a polite hourly sync and a guarded 'sync now', and the site keeps working when BGG does not."

<objective>
Add the server side of live updates chosen by the owner (D-09): a SignalR hub that only broadcasts the status payload when a sync starts and when it ends, with deliberate transports and a connection cap for a low-power, internet-facing host.

Purpose: open pages learn about any sync (hourly, another visitor's, their own) without polling; the page side follows in the next plan.
Output: hub, notifier, limiter, registration and settings, integration tests with the official .NET SignalR client, CSP coverage.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| internet -> /cabinet/live | Long-lived anonymous connections to a low-power host |
| client messages -> hub | Anything a client sends over the connection |
| sync -> broadcast | Server state pushed to every connected page |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-52 | Elevation of privilege | hub invocation | high | mitigate | No declared hub methods; tests prove every invocation fails and causes no BGG request |
| T-03-53 | Denial of service | connection flood | high | mitigate | Global admission cap in the hub plus Kestrel's upgraded-connection limit, no long polling, 1 KB messages, small buffers, short handshake and client timeouts; final sizes in the public-exposure work |
| T-03-54 | Information disclosure | broadcast payload | medium | mitigate | Same minimal status payload as the endpoint; sentinel test |
| T-03-55 | Spoofing | cross-site WebSocket to the hub | low | accept | The hub only pushes public, read-only status and accepts nothing; an origin allow-list needs the real host name and belongs to the public-exposure work |
| T-03-56 | Denial of service | broadcast failure blocking syncs | medium | mitigate | Notifier catches and logs by type name; publishing happens outside the coordinator lock |
| T-03-SC | Tampering | NuGet install (`Microsoft.AspNetCore.SignalR.Client` 10.0.12, test project only) | high | mitigate | Microsoft first-party, approved in the research legitimacy audit; lock file committed; never referenced by the shipped service |
</threat_model>
