## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| milestone branch -> main | Changes reach the release branch only through a checked pull request |
| owner approval -> published release | The only human gate between a tag and the server |
| container -> BGG | The first production calls with the real token |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-62 | Elevation of privilege | release publication | high | mitigate | Publication only by the owner's deploy-environment approval (Task 2, blocking, never auto-approved) |
| T-03-63 | Tampering | artefact in transit | high | mitigate | Draft verified on the workstation before approval; the container verifies the attestation again before installing |
| T-03-64 | Information disclosure | evidence and env file | high | mitigate | The env file is never read or printed; evidence is counts and statuses only; location check prints a count only |
| T-03-65 | Spoofing | merge and tag identity | medium | mitigate | Identity check on `origin/main` before tagging; noreply tagger |
| T-03-66 | Denial of service | first production sync | low | mitigate | One start-up run after jitter, paced at 5 s, shared cooldown, hourly cadence; the access check already measured BGG's behaviour for this application |
</threat_model>
