## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 3`): "The owner's real BGG owned collection appears automatically in the deployed cabinet, kept fresh by a polite hourly sync and a guarded 'sync now', and the site keeps working when BGG does not."

Purpose: answers LOC-02 and fixes the BGG-dependent settings (private info, units, User-Agent, 202 schedule) before any sync code is written.
Output: `.planning/phases/03-bgg-access-spike-real-sync-snapshot/03-SPIKE-OUTCOME.md`, signed off.
</objective>

  <action>
1. Probe: `ssh cabinet-lxc python3 --version`. If python3 is missing, stop and return a checkpoint asking the owner to choose between adding python3 to the provisioned packages and shipping the check as a release subcommand; do nothing else.
2. Run once: `ssh cabinet-lxc 'sudo -n -u cabinet python3 - --run' < build/bgg-access-check.py`, capturing stdout and the exit code into a file in the session scratchpad. Exit 3 means the env file lacks the keys: stop and tell the owner. Exit 4 means the guard withheld the report: do not retry; stop and report to the owner. Exit 5 means a stop rule fired: keep the partial report.
3. Show the owner the captured report verbatim (it is shape only by construction).
4. Write `03-SPIKE-OUTCOME.md` with these headings and nothing else:
   - `## Run`: date, the deployed release version reported by `ssh cabinet-lxc curl -s http://127.0.0.1:5081/health` (version only), duration, request count, exit code.
   - `## Decision table`: one row per question with the measured answer and the consequence, exactly these rows: private location readable with the token alone (yes/no, attribute name, how many items had a value) -> `Bgg:IncludePrivateInfo` true or false and the attribute the parser reads (D-04); version dimensions (share of items with a non-zero triple, value attribute or text, medians and ranges) -> millimetres-per-unit factor (25.4 when medians sit around 10-16 for the front sides and 1-4 for depth; 10 for centimetre-sized medians; 1 for millimetre-sized medians) (D-14); length versus width -> which one maps to standing height; User-Agent missing (G versus F) -> honest User-Agent stays mandatory either way; 202 count and seconds -> the 202 wait schedule and cap for the client; totalitems equals parsed count -> hard integrity check or warning only; default call D mislabels expansions -> two-call split confirmed; name form and entity artefacts -> names read as element text with or without decoding; 401 shape (H, I) and any 403/429 seen -> classification notes for the client.
   - `## Per-call shape summary`: the report's per-call lines, as printed.
   - `## Open items`: anything the run could not answer, including a distinct line if call A itself was rejected (token problem, phase blocked on the owner) versus only B lacking private info (location not readable).
   Do not commit yet.
  </action>
