1. `build/bgg-access-check.py` (Python 3 standard library only: `http.client`, `ssl`, `xml.etree.ElementTree`, `time`, `statistics`, `argparse`, `sys`; module docstring explains the purpose in plain words; no `#!` dependency on anything but `/usr/bin/env python3`). Implements D-03:
   - Modes as in the interfaces block. With no arguments print usage and exit 2.
   - `--run` parses the env file itself (skip blank lines and lines starting with `#`; split on the first `=`; strip one pair of matching quotes) for `Bgg__Token`, `Bgg__Username`, optional `Bgg__ContactUrl`. If token or username is missing, print `not configured` and exit 3 before any request. Nothing secret is ever taken from the command line or the environment of the calling shell.
   - Transport: one `http.client.HTTPSConnection("boardgamegeek.com", timeout=60)` per request (no redirect handling exists, so a 3xx is recorded and never followed); headers `Accept: text/xml, application/xml` and `Authorization: Bearer <token>` (only on this host, never anywhere else); honest `User-Agent: GamesCabinet-access-check/1` plus ` (+<contact url>)` when the contact URL is configured; a monotonic gap of at least 6 seconds between any two requests; a hard cap of 14 requests in total (further calls are recorded as `skipped: request budget reached`).
   - 202 handling per call: wait 5, 10, 20, 30, 30, 30 seconds between polls, at most 6 polls, each poll counting against the cap; record the number of 202 answers and the seconds until the final status.
   - Call plan, in this order, with these labels (the query values are built from the env file; the printed plan shows parameter names only): A `collection` own=1, excludesubtype=boardgameexpansion, stats=1, version=1; B same as A plus showprivate=1; C `collection` own=1, subtype=boardgameexpansion, stats=1, version=1; D `collection` own=1, stats=1 (no subtype filter); E `collection` own=1, showprivate=1, subtype=boardgameexpansion; F `thing` id=13 with the User-Agent; G `thing` id=13 without any User-Agent header; H `collection` own=1 without the Authorization header; I `collection` own=1 with the fixed wrong token value `invalid-token-for-shape-check`. Stop rule: a 401, 403 or 429 on any of A to G records the answer and stops the run (exit 5 after printing); H and I are expected to fail and end the run. Never contact the `www`-prefixed variant of the host. Never try to provoke a 429.
   - Body classes: `xml:items`, `xml:errors`, `xml:message`, `xml:other`, `html`, `empty`, `other`. Before parsing XML, reject any body containing `<!DOCTYPE` or `<!ENTITY` as `other` (no entity expansion). For `html` bodies record only booleans `mentions_cloudflare` and `has_form`.
   - Per call print: label, status, whole seconds, the response headers `content-type`, `content-length`, `cache-control`, `retry-after`, `server`, `cf-mitigated`, any `x-ratelimit-*` (names and values), and only the names of any `set-cookie` cookies; body byte length; body class. For `xml:items` additionally: `totalitems` and the names of other root attributes; parsed item count; whether they are equal; item attribute names with counts; child element names with their attribute names and counts; `subtype` value distribution; `status@own` distribution; the number of repeated `objectid` values and of repeated `collid` values; for `version`: items having one, for each of `width`, `length`, `depth` whether the number sits in a `value` attribute or the text, count non-zero, count zero, minimum, median, maximum of the non-zero numbers, and the count where `length >= width`; `name` form (text node or `value` attribute) and the count of names whose text still contains `&amp;` or `&#`; presence and form of `yearpublished`, `numplays`, `comment`, `image`, `thumbnail`; `privateinfo`: items having it, its attribute names, the count with a non-empty `inventorylocation`, the number of distinct non-empty values and the maximum value length (numbers only); `stats`: items having it and its attribute names. For C versus A print the count of collection ids present in both; for D print whether its item count equals A plus C and how many D items carry `subtype="boardgame"` while appearing in C.
   - Output guard: build the whole report as one string first. Collect a forbidden set: the token, the username, the contact URL, every title text and every location value seen in any body, plus the fixed wrong token. Withhold everything (print only `output withheld: it would have contained a sensitive value` and exit 4) when the report contains any forbidden value (titles shorter than 4 characters are matched as whole words, longer ones as substrings), the substring `http`, or a `<` character.
   - `--self-test`: runs the same summariser and guard over built-in synthetic bodies (an `items` answer with 3 invented base games including one duplicate `objectid` with two `collid` values, one `own="0"` item, version dimensions as `value` attributes with one zero triple, a `privateinfo` with `inventorylocation="Shelf A"`; an expansion answer; an `errors` answer; an HTML page mentioning Cloudflare) with sentinel credentials, then asserts the report has the expected counts and contains none of the invented titles, `Shelf A`, the sentinels, `http` or `<`; then proves the guard fires by feeding a report that contains a sentinel. Exit 0 only when every assertion holds; print each failed assertion's name otherwise.
2. `build/tests/bgg-access-check-test.sh` (bash, `set -euo pipefail`, shellcheck-clean, PASS/FAIL lines and a final count like the other script tests): runs `python3 build/bgg-access-check.py --self-test` (expects exit 0), `--plan` (expects exit 0, labels A to I present, no `=` value and no `http` in the output), no arguments (expects exit 2), and `--run --env-file` pointing at a temporary file without the BGG keys (expects exit 3 and no network use).

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server env file -> access check | The token and username are read on the container by the app user, never passed through the workstation |
| access check -> BGG XML API | One authenticated HTTPS conversation, token only to `boardgamegeek.com` |
| BGG answer -> printed report | Untrusted XML and HTML become a printed summary that the owner and the public repository may see |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-01 | Information disclosure | report output | high | mitigate | Report built as one string and withheld (exit 4) if it contains the token, username, contact URL, any title, any location, `http` or `<`; proven by `--self-test` with sentinels |
| T-03-02 | Information disclosure | token transport | high | mitigate | Single fixed host `boardgamegeek.com` over HTTPS via `HTTPSConnection`, no redirect following exists, no `www` host, wrong-token call uses a fixed dummy value |
| T-03-03 | Denial of service | BGG application quota | medium | mitigate | 6-second minimum gap, 14-request cap, 202 back-off schedule, stop on 401/403/429, owner approval of the exact run (Task 2) |
| T-03-04 | Tampering | hostile XML in a BGG answer | medium | mitigate | Bodies with DOCTYPE or ENTITY declarations are classified `other` and never parsed |
| T-03-05 | Information disclosure | docs page | low | mitigate | Placeholder `<container>` instead of the alias; no hostnames, addresses or usernames (repo lint plus pre-commit denylist) |
</threat_model>
