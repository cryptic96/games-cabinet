## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 3`): "The owner's real BGG owned collection appears automatically in the deployed cabinet, kept fresh by a polite hourly sync and a guarded 'sync now', and the site keeps working when BGG does not."

<objective>
Keep the cabinet standing when BGG does not: classify every way a sync can fail, poll queued answers politely within a cap, and hold back empty or more-than-halved results until they are confirmed (SYNC-04, D-11, D-12, D-24).

Purpose: the cabinet must never be wiped or shrunk by a bad or partial BGG answer.
Output: failure classification and the 202 loop in the client, content checks in the parser, the pure shrink guard, held-back handling in the runner and coordinator, tests, and the operations notes including the manual step for a genuinely emptied collection.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| BGG answer -> stored collection | The only path by which the public cabinet changes |
| BGG availability -> server load | Queued and failing answers drive how many requests the server makes |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-03-40 | Tampering | poisoned, truncated or challenge answers replacing the snapshot | high | mitigate | Status, content type, root, totalitems and XML checks; every failure leaves snapshot and ETag unchanged (integration tests per class) |
| T-03-41 | Tampering | empty or shrunken answers wiping the cabinet | high | mitigate | Pure `ShrinkGuard` before any write; empty never accepted once games exist; more-than-half removals need the same id set twice |
| T-03-42 | Denial of service | runaway polling of BGG | medium | mitigate | Bounded 202 schedule through the shared pacer, 16-request budget per sync, 10-minute run timeout, stop on 401/429/503 |
| T-03-43 | Information disclosure | failure details | medium | mitigate | Only categories are logged and stored; visitors see only `failed` or `heldBack` in the status |
| T-03-44 | Repudiation | operator unaware of a held-back result | low | mitigate | Held-back record with time persisted in `sync-state.json`; the page shows the held-back note (page plan); docs explain it |
</threat_model>

## Flagged Assumptions

- The 202 wait schedule and the totalitems rule come from the signed-off outcome; the defaults above apply where the outcome observed no 202 answers.
- 503 is treated as throttling (research section 3, BGG API2 wiki note); if BGG uses 503 for plain outages, the only effect is the run ending early, which the hourly cadence absorbs.
