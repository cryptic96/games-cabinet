## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| pull request -> main | Even a deliberate break lands only through required checks |
| owner approval -> immutable release | The broken release is published only by the owner |
| installer -> running app | Health failure must lead to rollback, never to a looping reinstall |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-111 | Denial of service | broken release on the server | high | mitigate | Health timeout triggers automatic rollback; rejected marker stops reinstall loops; verified by two skip polls with unchanged ActiveEnterTimestamp |
| T-01-112 | Elevation of privilege | hidden unhealthy switch | medium | mitigate | Break is an ordinary committed configuration change reviewed in a pull request; no code path forces unhealthy |
| T-01-113 | Repudiation | broken release in public list | low | mitigate | Draft notes labelled as a rollback rehearsal before approval |
| T-01-114 | Information disclosure | evidence in SUMMARY | medium | mitigate | Hostnames, addresses and usernames removed before recording |
</threat_model>
