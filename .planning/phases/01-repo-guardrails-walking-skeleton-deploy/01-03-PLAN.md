## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 1`): "A public repository with enforced guardrails and a proven release pipeline, so a hello page travels from semver tag to approved release to running LXC (and back via rollback) before any feature depends on it."

<objective>
Build the walking skeleton's application end: a .NET 10 Razor Pages hello page that shows its running version, a loopback-only ops listener whose `/health` reports status, version and commit as JSON, the SkiaSharp image-smoke subcommand (D-17), and the release packaging script, all proven by running the packaged zip from a symlinked release directory exactly as the server will.

Purpose: this is the contract the installer health-checks and the artefact the release pipeline attests; everything later in the phase consumes it.
Output: `Cabinet.slnx` with Domain, Repository, Service, UnitTests and IntegrationTests projects (D-02), `build/package-release.sh`, `build/tests/package-release-e2e-test.sh`.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reverse proxy -> public listener | Forwarded headers arrive from Traefik; only that address may set them |
| host -> ops listener | Health is reachable on loopback only |
| NuGet -> build | Third-party packages enter the build here |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-031 | Spoofing | ForwardedHeaders | medium | mitigate | XForwardedFor and XForwardedProto honoured only from ReverseProxy:KnownProxies with ForwardLimit 1; invalid entries fail startup |
| T-01-032 | Information disclosure | /health | medium | mitigate | UseHealthChecks bound to the ops port; OpsEndpoint refuses non-loopback URLs; integration test asserts 404 on the public port |
| T-01-033 | Denial of service | health contract | medium | mitigate | Health has no external or state dependency, so a BGG outage or empty disk can never roll back a good release |
| T-01-034 | Tampering | image decoding | low | accept | Only synthetic in-process images are decoded in this phase; untrusted image handling is designed with the image pipeline later |
| T-01-SC | Tampering | NuGet installs (SkiaSharp, xunit.v3, FluentAssertions, Mvc.Testing) | high | mitigate | Exact pinned versions, committed packages.lock.json with locked-mode restore in packaging, prefix-reserved publishers (SkiaSharp owner-verified per D-17, others audited in research), vulnerable-package listing must be empty |
| T-01-035 | Elevation of privilege | production switches | medium | mitigate | No configuration or code path exists to force unhealthy; the rehearsal breaks a release with an ordinary configuration diff instead |
