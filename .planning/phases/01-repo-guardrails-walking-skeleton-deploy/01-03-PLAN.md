## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 1`): "A public repository with enforced guardrails and a proven release pipeline, so a hello page travels from semver tag to approved release to running LXC (and back via rollback) before any feature depends on it."

<objective>
Build the walking skeleton's application end: a .NET 10 Razor Pages hello page that shows its running version, and a loopback-only ops listener whose `/health` reports status, version and commit as JSON, with the project names fixed by D-02 and a health contract that can never be forced unhealthy (D-11).

Purpose: this is the contract the installer health-checks and the page the owner opens from the home network; release packaging, the image smoke and the contract tests all build on it.
Output: `Directory.Build.props`, `global.json`, `.gitignore`, the `Cabinet.Domain` and `Cabinet.Service` projects with their lock files. The solution file arrives with release packaging, when the first test project joins.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| reverse proxy -> public listener | Forwarded headers arrive from Traefik; only that address may set them |
| host -> ops listener | Health is reachable on loopback only |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-031 | Spoofing | ForwardedHeaders | medium | mitigate | XForwardedFor and XForwardedProto honoured only from ReverseProxy:KnownProxies with ForwardLimit 1; invalid entries fail startup (acceptance criterion) |
| T-01-032 | Information disclosure | /health | medium | mitigate | UseHealthChecks bound to the ops port; OpsEndpoint refuses non-loopback URLs; the verify asserts 404 on the public port and the contract tests pin it |
| T-01-033 | Denial of service | health contract | medium | mitigate | Health has no external or state dependency, so a BGG outage or empty disk can never roll back a good release |
| T-01-034 | Elevation of privilege | production switches | medium | mitigate | No configuration or code path exists to force unhealthy; the rehearsal breaks a release with an ordinary configuration diff instead |
</threat_model>
