Output: `.githooks/` (library plus three hooks), `build/tests/githooks-test.sh`, `docs/development.md`, local `core.hooksPath` set.
</objective>

    - Added line containing a denylisted string in different letter case: commit refused, exit non-zero, stderr names file, line and `denylist match #N`, not the string.
    - Clean added lines: commit succeeds.
    - Staged file whose path contains a denylisted string: commit refused.
    - Deleted line containing a denylisted string (diff line starting with a single minus): commit succeeds.
    - Denylist file absent: stderr contains `warning` and the commit succeeds.
    - Denylist with only comments and blank lines: commit succeeds without warning.
  </behavior>
  <action>
1. Create `.githooks/lib/denylist.sh` (sourced, not executable on its own) with functions: `denylist_path` (prints the resolved path from the shared contract), `denylist_load` (prints the patterns, comments and blanks stripped, or returns 3 when the file is absent or unreadable), `denylist_scan` (reads text on stdin with a location label argument; for each pattern N uses `grep -n -i -F -e` on the captured text; prints `<label>:<line>: denylist match #N` per hit; returns 1 on any hit). Patterns are always fixed strings (never regex).
2. Create `.githooks/pre-commit` (extensionless, executable): resolve its own directory, source `lib/denylist.sh`; when the denylist is absent print `warning: personal-data denylist not found at <path>; skipping the check` to stderr and exit 0; otherwise scan the added lines only of `git diff --cached -U0 --no-color` (lines starting with a single `+`, excluding `+++` headers, labelled with the file name from the preceding header) and the output of `git diff --cached --name-only`; on any hit print `blocked: staged content matches the personal-data denylist` and exit 1.
3. Create `build/tests/githooks-test.sh`: builds a throwaway repository in `mktemp -d` (trap cleanup), sets `core.hooksPath` to this checkout's `.githooks` (absolute path, quoted), points `CABINET_DENYLIST_FILE` at a synthetic denylist made from invented fragments joined with `printf`, configures a throwaway noreply-style identity, and runs one `check` per behaviour above, printing `PASS:`/`FAIL:` lines and exiting 1 on any failure.
  </action>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| developer workstation -> local history | Staged content and messages enter history here; the hooks are the gate |
| local history -> remote | The pre-push hook is the last local gate before content leaves the machine |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-021 | Information disclosure | .githooks/pre-commit, commit-msg | high | mitigate | Case-insensitive fixed-string scan of added lines, staged names and messages against the owner's denylist |
| T-01-022 | Information disclosure | hooks skipped with --no-verify | high | mitigate | pre-push rescans every unpushed commit's patch, message and identity; build/scan-history.sh runs again before the first push |
| T-01-023 | Information disclosure | hook output | medium | mitigate | Output names file, line and denylist line number only, never the value |
| T-01-024 | Spoofing | commit identity | medium | mitigate | pre-push refuses non-noreply author or committer emails regardless of denylist presence |
| T-01-025 | Tampering | denylist patterns | low | mitigate | Patterns are passed to grep as fixed strings (-F -e), so a pattern is never interpreted as a regular expression or a grep option |
| T-01-026 | Denial of service | fresh clones and CI without a denylist | low | accept | Hooks warn and allow; CI relies on generic gitleaks rules instead (the denylist can never be in CI) |
</threat_model>
