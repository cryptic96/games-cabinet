## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 1`): "A public repository with enforced guardrails and a proven release pipeline, so a hello page travels from semver tag to approved release to running LXC (and back via rollback) before any feature depends on it."

<objective>
Run the walking skeleton for real: tag `v0.1.0` (D-13), let the release workflow build, attest and draft it, have the owner approve publication, and watch the container's poll timer find, verify, install and health-check it, ending with a passing on-host selfcheck and the hello page loading from the home network through the LAN-only Traefik route (D-09).

Purpose: this is the end-to-end proof of OPS-03, OPS-04 and OPS-05 on real infrastructure.
Output: published immutable release v0.1.0, a provisioned container running it, selfcheck and journal evidence (sanitised) in the SUMMARY.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| owner approval -> published release | The only human gate between a tag and the server |
| GitHub and Sigstore -> container | The container pulls public artefacts and the Sigstore trust root |
| LAN and VPN clients -> Traefik -> app | Only allow-listed clients reach the hello page |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-101 | Elevation of privilege | release publication | high | mitigate | Publication only through the owner's own deploy-environment approval; Task 2 is a blocking owner decision |
| T-01-102 | Tampering | artefact in transit | high | mitigate | Draft verified on the workstation with the server's exact flags before approval; the container verifies again before unpacking |
| T-01-103 | Information disclosure | evidence in SUMMARY | medium | mitigate | Hostnames, addresses and usernames removed before recording; container reached only by an alias kept in the owner's SSH config |
| T-01-104 | Spoofing | LAN route | medium | mitigate | Traefik ipAllowList and the container firewall admit the app port only from Traefik; human check confirms refusal from outside |
| T-01-105 | Denial of service | Sigstore unreachable from the container | low | accept | Verification fails closed and the poll retries next cycle; reachability is confirmed by this first install |
</threat_model>
