## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 1`): "A public repository with enforced guardrails and a proven release pipeline, so a hello page travels from semver tag to approved release to running LXC (and back via rollback) before any feature depends on it."

<objective>
Port the reference project's idempotent provisioning framework for the new LXC (D-07, D-10): the orchestrator with its allow-list config parser and validators, the packages, accounts and firewall modules, the nftables and Traefik templates (D-09), the pinned versions file, and their offline and network tests. The services module, systemd units and selfcheck follow in a later plan that builds on this framework and on the installer.

Purpose: a fresh LXC must be provisionable from repeatable scripts alone, with real values living only in the server-side `provision.conf`.
Output: `deploy/provision.sh`, `deploy/provision.d/{10,20,50}-*.sh`, templates, examples, `deploy/versions.env`, `deploy/tests/lib/host-guard.sh` and three test scripts.
</objective>

## Conventions for every file this plan writes

- No planning references outside `.planning/` (requirement keys, decision IDs, phase or plan numbers, planning document names) in scripts, templates, examples, comments or messages.
- Shell: `set -euo pipefail`, quote every expansion (the checkout path contains a space), arrays for argument lists, `#` comments allowed, shellcheck-clean with `-x` and source hints. Under `pipefail` never pipe into `grep -q`; capture then match.
- Placeholders only: `example.com` hostnames and RFC 5737 addresses (192.0.2.0/24, 198.51.100.0/24, 203.0.113.0/24) in every template, example and test. Never copy a hostname, range or address from the reference.
- The GitHub CLI key fingerprint is copied into `deploy/versions.env` only (the generic scanner allow-lists it there); never repeat it elsewhere.
- Offline tests source `deploy/tests/lib/host-guard.sh` first and assert at the end that no `systemctl` or `pkexec` call was recorded.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| server-side config file -> root provisioning | provision.conf is edited by hand and read by root scripts |
| apt repositories -> host | Packages and keys are fetched from the network |
| LAN and VPN -> LXC | SSH and the app port are the only inbound surfaces |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-01-071 | Elevation of privilege | provision_load_conf | high | mitigate | Allow-list parser that never sources the file, refuses unknown keys, backticks, command substitution and insecure ownership or modes |
| T-01-072 | Tampering | template rendering | medium | mitigate | provision_validate_safe_value rejects `;`, braces and newlines; unreplaced placeholders fail rendering |
| T-01-073 | Tampering | GitHub CLI apt source | high | mitigate | Fingerprint-pinned key in a dedicated keyring with signed-by; expired keys handled; installed version floor asserted; network test re-verifies the pin |
| T-01-074 | Spoofing | SSH | high | mitigate | nftables accepts SSH only from configured admin ranges; key-only authentication is enforced and checked by the selfcheck added later |
| T-01-075 | Information disclosure | ops listener | medium | mitigate | No firewall rule for the ops port; it listens on loopback only |
| T-01-076 | Information disclosure | templates and examples | medium | mitigate | Placeholders only (example.com, RFC 5737); render test asserts no other addresses; real values only in server-side files |
| T-01-077 | Denial of service | offline tests on the developer host | low | mitigate | host-guard stand-ins refuse systemctl and pkexec and the tests assert no calls were made |
</threat_model>
