## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 2`): "A deterministic, natural-looking cabinet layout, built on synthetic data while the BGG approval is pending, that the owner has reviewed and approved visually from an empty cabinet up to several hundred games, on desktop and phone widths."

<objective>
Ship the approved prototype through the existing release path (pull request into `main`, semver tag, attested draft, owner approval, container pull) and close the phase with the owner's check of the deployed cabinet on a desktop browser and a phone (D-18).

Purpose: the phase's acceptance gate is the owner's approval of the real, deployed thing, not of screenshots; the release pipeline is reused unchanged.
Output: a merged milestone pull request, a published immutable 0.x release, the container running it with health and selfcheck evidence (sanitised), the owner's final approval, and the prototype removal list in the SUMMARY.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| milestone branch -> main | Changes reach the release branch only through a checked pull request |
| owner approval -> published release | The only human gate between a tag and the server |
| GitHub and Sigstore -> container | The container pulls public artefacts and verifies them |

## STRIDE Threat Register

| Threat ID | Category | Component | Severity | Disposition | Mitigation Plan |
|-----------|----------|-----------|----------|-------------|-----------------|
| T-02-26 | Elevation of privilege | release publication | high | mitigate | Publication only through the owner's own deploy-environment approval; Task 2 is a blocking-human checkpoint that is never auto-approved |
| T-02-27 | Tampering | artefact in transit | high | mitigate | Draft verified on the workstation with the server's exact flags before approval; the container verifies the attestation again before installing |
| T-02-28 | Spoofing | merge and tag identity | medium | mitigate | Identity check on `origin/main` before tagging; noreply tagger; escalate on any other identity |
| T-02-29 | Information disclosure | evidence in SUMMARY | medium | mitigate | Hostnames, addresses, usernames and local paths removed before recording; the container is reached only through an alias kept in the owner's SSH config |
| T-02-30 | Information disclosure | prototype on the deployed site | low | accept | The route stays LAN and VPN only until the public-exposure work; the prototype shows invented data and is switched off by one setting once real data arrives (removal list recorded) |
</threat_model>
