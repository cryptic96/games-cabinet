## Phase Goal

ROADMAP goal (not yet in user-story form; flagged, see `/gsd mvp-phase 2`): "A deterministic, natural-looking cabinet layout, built on synthetic data while the BGG approval is pending, that the owner has reviewed and approved visually from an empty cabinet up to several hundred games, on desktop and phone widths."

<objective>
Run the owner's screenshot review loop (D-18): produce screenshots of every invented collection at desktop and phone widths with automated geometry and strict-CSP checks, let the owner approve or request tuning, apply tuning rounds within the tuning register, and repeat until the owner approves.

Purpose: visual quality is the phase's acceptance gate and it is subjective; screenshots between rounds keep iterations cheap before a release is cut.
Output: approved look (recorded in the SUMMARY with the final tuning values and round count), any tuning commits with raised layout versions and re-recorded goldens, and the owner's consent to merge and tag.
</objective>

## Conventions for this plan

- Screenshots, scripts and the Playwright install live only in the executor's session scratch directory; nothing from them is committed. Screenshots show invented data only.
- Every tuning commit follows the repository rules: `///` comments only, no `//` in scripts, no planning references, invented data, noreply identity, hooks active, branch `milestone/v1-games-cabinet`.
- Locked decisions (CONTEXT.md D-01 to D-19) and the strict-CSP rules are not tuning knobs. A request that would break one is explained to the owner and confirmed before anything changes.
- Local runs: the built app in Development on 127.0.0.1:6180 (public) and 6181 (ops).
